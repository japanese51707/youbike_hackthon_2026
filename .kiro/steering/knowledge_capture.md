# 知識沉澱規則

每當討論產生「可重用於未來專案的通用知識」時，主動把它沉澱下來，避免知識流失。

## 何時觸發
- 討論中形成了一個「不只適用本專案、未來別的專案也用得到」的原則、模式或判準
- 解決了一個容易重犯的坑
- 確立了一個設計決策背後的通用邏輯

## 沉澱到哪
1. **Obsidian**（`彼得潘的第二大腦/20 Knowledge/Concepts` 或 `Workflows`）
   - 寫成原子筆記：一個檔案一個核心觀點
   - 用 frontmatter（type/created/updated/topics/status）
   - 至少連結一個相關知識或 MOC
   - 遵循 vault 既有風格：核心觀點 → 解釋 → 判準 → 相關知識
2. **Notion**（團隊可共享版本）
   - 過濾私人資訊後的精簡版

## 原則（沿用 vault 的「三層知識流」）
- Sources 存「別人說了什麼」；Knowledge 存「我們學到了什麼」
- 通用知識與專案細節分開：專案細節放 `30 Projects`，通用原則放 `20 Knowledge`
- 不保存逐字對話，只留收斂後的決策與原則

## 提醒使用者的時機
- 一個段落的討論告一段落、且產生了通用價值時，主動說：「這個可以沉澱成知識，要我存進 Obsidian 嗎？」
- 由使用者確認後再寫入（避免製造雜訊）
