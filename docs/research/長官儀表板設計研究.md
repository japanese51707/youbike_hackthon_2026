# 長官／營運總覽儀表板 — 設計研究筆記

> 目的：整理「給主管機關長官看的營運總覽」該呈現什麼、怎麼呈現，作為前端長官導覽面板（`/overview`）的設計依據。
> 範圍：通用 executive dashboard 原則 + 公共自行車營運 KPI + 對本專案 mock 資料的對照。
> 內容為外部資料改寫摘要（非原文照抄），來源見文末。

---

## 一、Executive dashboard 通用原則

高層儀表板與「操作型工作台」不同，重點在**決策而非監看**：

1. **四問原則**：能在幾分鐘內回答「達標了嗎／哪裡沒達標／為什麼／下一步該做什麼決策」。
2. **少即是多**：只放能影響領導決策的指標；聚焦**結果、異常、趨勢**，不是把每個數字都塞上去。
3. **秒懂 + 可下鑽**：幾秒看懂重點，再點開看原因（drill-down）。
4. **主動示警**：凸顯門檻突破、風險、異常，直接指出該關注哪裡。
5. **目標對照**：關鍵指標要有「目標值 / 燈號」，才知道是否達標。

## 二、公共自行車營運核心 KPI

調度研究一致指向核心是**服務水準（service level）**：讓民眾在站點「借得到車、也還得到位」，靠把車從滿站移到空站的**再平衡（rebalancing）**維持。常見指標：

- **服務水準／可用度**：站點「有車且有空位」的站時比例；反面是**空站（借不到）**與**滿站（還不到）**。
- **再平衡成效**：調度後空/滿站的減少幅度、每次調度移動車數、每台移動成本。
- **未滿足需求**：因無車/無位而流失的租借次數。
- **使用率／周轉**：每台車周轉次數、站點使用率。
- **成本效率**：里程、油資、人力工時 vs 改善幅度。

## 三、長官（政府主管機關）視角的關注點

比企業高層更偏**市民服務與問責**：

| 類別 | 長官關注 |
|---|---|
| A 市民服務水準（最重要） | 借得到/還得到的比例；空/滿站造成多少「借不到、還不到」 |
| B 成效 vs 過去/目標 | 上線後有沒有變好、有沒有達標（Before/After、達標燈號） |
| C 資源與效率（預算問責） | 人力、車輛、油資、里程換到多少改善；每次調度效益 |
| D 熱點與風險（施政重點） | 哪些行政區/站最常出問題、哪裡該加柱位或加派 |
| E 趨勢與異常 | 在改善還是惡化；今天有沒有特別糟的地方 |
| F 對外交代/治理 | 活動因應、緊急覆寫稽核紀錄 |

## 四、對照本專案 mock 資料（誠實盤點）

| 長官想看 | 現況 | 做法 |
|---|---|---|
| 空站率/滿站率、需調度數 | ✅ 有（kpi） | 直接呈現，加達標燈號 |
| Before/After 成效對比 | ✅ 有（simulation_replay） | 保留＋改善幅度換算 |
| 任務量/人力/油資/里程 | ✅ 有（today_totals/operators） | 資源效率區 |
| 活動影響、稽核紀錄 | ✅ 有 | drill-down 分頁 |
| 按行政區彙總熱點 | 🟡 可由 stations 現算 | 前端彙總（誠實、不需新資料） |
| 達標燈號（vs 目標值） | 🟡 需目標值 | 先用 **Demo 目標值**，明確標示待交通局定義 |
| 服務水準%（站時有車有位比例） | 🔴 需真資料（station-hours） | 標「待接真實資料源」 |
| 未滿足需求（流失租借） | 🔴 需真資料 | 標「待接真實資料源」 |
| 跨日/跨週趨勢 | 🔴 需歷史序列 | 標「待接真實資料源」 |

## 五、落到前端的設計決定（長官導覽面板）

無捲動、四區、可點開細節：

1. **服務水準頭條**：空站率/滿站率 + 達標燈號、需調度站數、一句結論。（回答「達標了嗎」）
2. **Before/After 成效** + 改善幅度標籤。（回答「有沒有變好」）
3. **熱點行政區**：由站點現算的問題站排行，點開看該區站點。（回答「哪裡要關注」）
4. **人力與成本**：人力狀態 + 里程/油資/每台移動成本。（回答「投入與問責」）

> 誠實性：達標目標值標為 Demo；服務水準%、未滿足需求、跨日趨勢屬待接真實資料，先不假造。
