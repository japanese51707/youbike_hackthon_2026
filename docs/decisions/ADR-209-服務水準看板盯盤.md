# ADR-209：`/overview` 改為服務水準看板（值班處長盯盤）

## 背景與問題

ADR-205 把 `/overview` 定成「長官導覽面板」：宏觀 KPI、Before/After 模擬、時間軸。
API 模式下實際卻是 `BackendOverviewPage`（空滿站數字 + **派工紀錄清單**）。
名稱像帶長官參觀系統；內容像調派員底稿。owner 認為兩者都不是上層需要的。

## 決策

1. **顯示名稱**：服務水準看板。路由維持 `/overview`。
2. **觀眾**：值班處長**盯盤**（間歇看、要自動刷新），不是簡報導覽、不是調派員工作台。
3. **頁面只回答四句話**：市民借得到／還得到嗎；哪幾區該被看見；今天調度有沒有把火壓下來；有沒有該拍板的事（本輪拍板列在頭條與行政區，不另開決策單）。
4. **畫面只留三塊**：
   - 頭條一句人話 + 空站／滿站／健康率燈號
   - 行政區壓力排行（點開才看該區站名）
   - 今日調度結果（完成／進行中／仍空仍滿、當班人力）—**沒有任務列表**
5. **不放**：派工確認、細站操作、戰情室炫技、沒有真實評估資料的 Before/After 或節省%、油資甜甜圈、AI 助理、稽核 log 牆。
6. **不派工**（守 ADR-004）。自動刷新間隔與調度面板同為 60 秒。
7. 本頁不接 LLM（ADR-301 長官頁 LLM 仍待定；本決策是拿掉本頁助理）。

## 理由與判準

- 處長要的是市民服務與哪區失火，不是參觀系統或翻工單。
- 沒有真實 Before/After 就不造數字。
- 名稱「服務水準看板」對齊公共自行車問責（借得到／還得到），不像「長官導覽」。

## 考慮過的替代方案

### 維持長官導覽＋Mock 四區

- 未採用原因：owner 否決名稱與現況內容。

### 營運決策看板／服務成果看板

- 未採用原因：本頁是盯盤不是簡報；「服務水準」比「成果」更貼空滿站。

## 影響與後果

### 正面

- 選單與頁面語意對齊處長。
- API 模式不再掉進派工清單。

### 負面與代價

- 舊 Mock 成效圖／助理從此不當本頁主體。
- 行政區壓力需拉全市站點，與調度面板同樣 60 秒一輪。

### 尚未解決

- 真實站時服務水準%、未滿足需求、跨日趨勢（無資料不造）。
- 達標門檻仍是參考值，待交通局定義。

## 介面與相容性

- 前端選單與頁標題改名；後端 API 不改。
- 讀既有 `GET /kpi`、`GET /stations`、`GET /dispatch/overview`。

## 資安與隱私

- 只讀；不擴大寫入權限。

## 回復或取代方式

- 以新 ADR 改名或改定位，不改寫本 ADR。

## 驗證方式

- 選單顯示「服務水準看板」。
- `/overview` 有人話頭條、行政區排行、調度結果，沒有任務列表。
- 60 秒內數字會隨後端更新。
