# ADR-127：不採用 conformal 校準，並訂定覆蓋率的判讀規則

## 背景與問題

ADR-125 主張：預測區間的邊際覆蓋率合格（80.8～81.2%，名目 80%），
但「觀測 Δ≠0」的列只有 67.9%（30 分）～75.3%（120 分），屬**條件覆蓋率**問題，
應以分組 conformalized quantile regression（Mondrian CQR）修正，分組變數用 `|P50 − 現況|`。

該機制已依 ADR-125 完整實作並通過單元測試。實測之後發現：**這個判斷是錯的，而且錯在方法論層次。**
若不記錄，未來會有人再次照 ADR-125 的敘述去開啟校準，或再次用同樣的方式判讀覆蓋率而得到同樣的錯誤結論。

## 決策

沿用 ADR-002、107、111、121、122；**取代 ADR-125**。

1. **不採用 conformal 校準**。移除 serving 端的套用邏輯、`config.prediction` 的相關旗標，
   以及 `train_save` 為此切出校準窗口的流程；模型恢復以全部乾淨訓練列訓練。
2. **保留 `backend/prediction/conformal.py` 作為量測用函式庫**（CQR 的實作與單元測試），
   因為重現本 ADR 證據的 `tools/fullscale_eval/conformal_check.py` 依賴它。
   它**不接在 serving 上、沒有開關**；未來若真要啟用，必須另立新 ADR。
3. **訂定覆蓋率的判讀規則**（本 ADR 的主要價值）：
   - 評估區間校準時，只採計**邊際覆蓋率**與**「以推論時算得出來的變數」分組後的條件覆蓋率**。
   - **不得以「用標籤本身選出來的子集」判斷校準**，例如「Δ≠0 的列」「預測誤差大的列」
     「實際出事的列」。這類子集是依變數選樣（selection on the outcome），
     任何覆蓋率正確的區間在其上都必然覆蓋不足；這不是缺陷，也沒有任何無分布方法能修正
     （對 Y 的條件覆蓋率在無分布假設下不可得）。
   - 要回答「站點真的在動時模型準不準」，應該用**點估計的誤差指標**（如 Δ≠0 子集的 MAE，
     第三批已在做），而不是覆蓋率。
4. **ADR-122 §7 的評估協定不變**：主指標排除補值標籤、截斷列另外拆開報，這些都成立且繼續適用。
   本 ADR 只否定「用 Δ≠0 覆蓋率判斷校準」這一個判讀方式。

## 理由與判準

- **證據明確**：偏移全為 0，且七個可觀測分組變數的每一個十分位覆蓋率都落在 79.5～83.0%。
- **錯在方法論而非參數**：換分組變數、換桶數、換校準集都救不回來，因為問題不在實作。
- **留著錯誤前提的 accepted ADR 比沒有更危險**：它會引導未來的人去開啟一個不需要的機制。
- **保留量測能力**：否定的是「校準」這個動作，不是「量測校準」這件事。

## 實測證據

候選 booster 只用 1～5 月訓練，6 月完全沒被看過，因此把 6 月隨機切半（前半校準、後半驗證），
是有效的 split-conformal 設定。可信標籤（排除補值與截斷列）共約 430 萬列。

### 一、CQR 偏移全為 0，四個視野都沒有任何改變

| 視野 | 校準／驗證列數 | 分桶偏移 | 整體覆蓋率 | Δ≠0 覆蓋率 | 平均區間寬 |
|---|---|---|---|---|---|
| 30 分 | 1,075,528 / 1,075,529 | [0, 0, 0, 0] | 81.1% → 81.1% | 67.9% → 67.9% | 4.43 → 4.43 |
| 60 分 | 1,081,311 / 1,081,311 | [0, 0, 0, 0] | 81.2% → 81.2% | 72.4% → 72.4% | 6.47 → 6.47 |
| 90 分 | 1,084,460 / 1,084,460 | [0, 0, 0, 0] | 80.9% → 80.9% | 74.1% → 74.1% | 7.78 → 7.78 |
| 120 分 | 1,086,579 / 1,086,580 | [0, 0, 0, 0] | 80.7% → 80.7% | 75.3% → 75.3% | 8.76 → 8.76 |

偏移為 0 是 CQR 的**正確**行為：區間已達名目覆蓋率時，conformity score 的 80% 分位數本來就 ≤ 0。

### 二、七個可觀測分組變數都分離不出覆蓋不足的列（60 分視野）

| 分組變數 | 覆蓋率離散 | 各十分位覆蓋率 |
|---|---|---|
| 站點周轉量 | 2.9pp | 82.9 83.0 82.2 81.1 80.9 80.3 80.6 80.4 80.4 80.1 |
| 區間寬度 hi−lo | 2.8pp | 83.0 80.2 81.6 81.5 81.1 80.8 80.9 80.9 80.8 81.0 |
| 借用率 | 2.7pp | 79.5 80.7 81.3 81.4 81.9 82.0 82.2 81.8 81.4 79.8 |
| \|P50 − 現況\|（ADR-125 原提案） | 2.0pp | 81.3 82.0 81.6 81.2 81.4 81.1 80.7 81.1 80.0 |
| \|近 2 小時變化\| | 1.7pp | 82.2 81.2 80.9 80.8 80.7 80.5 |
| \|近 1 小時變化\| | 1.1pp | 81.8 81.0 80.8 80.8 80.7 |
| \|station_slot_p50\| | 0.0pp | 81.2 |

**每一個可觀測切面的每一個十分位，覆蓋率都在 79.5～83.0% 之間**——模型在所有看得到的維度上都校準良好。

### 三、為什麼 Δ≠0 的覆蓋率一定比較低

`Δ≠0` 等價於「真值不等於區間中心附近的那個值」。用真值挑出來的子集，本來就偏向真值離中心遠的樣本，
覆蓋率必然低於整體。這對任何校準良好的區間都成立，與模型好壞無關。舉例：一個完美校準的 80% 區間，
若只看「真值落在區間外或接近邊界」的列，覆蓋率當然遠低於 80%——那是定義造成的，不是模型的問題。

原始數據：[`phase4_conformal/`](../analysis/phase4_conformal/)；
重現：`tools/fullscale_eval/conformal_check.py`（偏移實測）與 `grouping_probe.py`（分組分離能力）。

## 考慮過的替代方案

### 方案 A：維持 ADR-125 為 accepted，程式保留但旗標關閉

- 優點：不動已完成的工作。
- 缺點：留下一份前提已被推翻的 accepted ADR，未來會引導別人去開啟不需要的機制。
- 未採用原因：owner 明確表示「既然是錯的就不要留」。

### 方案 B：把 ADR-125 直接改成 rejected

- 優點：一份文件解決。
- 缺點：違反 decision_governance §6——ADR-125 當時確實被核准且已實作，直接改寫會讓歷史看似從未發生。
- 未採用原因：治理規範要求以新 ADR supersede。

### 方案 C：連 `conformal.py` 一併刪除

- 優點：最徹底。
- 缺點：本 ADR 的證據必須靠它才能重現；未來若模型真的失準，得重寫一次。
- 未採用原因：保留為不接線的量測函式庫，成本接近零。

## 影響與後果

### 正面

- 沒有前提錯誤的 accepted 決策留在索引中。
- 覆蓋率的判讀規則被明文固定，同樣的誤判不會再發生一次。
- serving 少一條分支與四個設定項，模型包不需要多帶 `conformal.json`。

### 負面與代價

- 失去「一鍵開啟校準」的能力；未來若需要，要重新接線並另立 ADR。
- ADR-125 的實作工時成為沉沒成本（但換得一個明確的反證與判讀規則）。

### 尚未解決

- 若未來重訓後的模型在可觀測分組上出現真正的校準不良，需要重新評估是否接回 CQR（須另立 ADR）。
- 「站點真的在動時準不準」的正確衡量方式（Δ≠0 子集的 MAE）已在第三批實施，但尚未設定改善目標。

## 介面與相容性

移除 `config.prediction` 的 `套用conformal校準`／`校準窗口天數`／`分組桶數`／`分組最小樣本數`，
以及 `PredictionInterval.calibration` 欄位與 serving 端的套用邏輯；
`train_save` 恢復以全部乾淨訓練列訓練，不再切出校準窗口。
`backend/prediction/conformal.py` 保留為不接線的函式庫。既有模型包不受影響，
因為從未產出過 `conformal.json`；前端從未讀取 `calibration` 欄位，移除無影響。

## 資安與隱私

無。

## 回復或取代方式

要重新採用 conformal，必須另立新 ADR 並重新接線；不得僅憑本 ADR 或 ADR-125 的存在就開啟。
本 ADR 的判讀規則若要修改，同樣以新 ADR supersede。

## 驗證方式

- `backend/tests/test_conformal.py` 保留 CQR 的數學性質測試（覆蓋率保證、偏移非負、分組、成套檢查）。
- 移除 serving 旗標相關測試；全套 pytest 應維持全綠。
- `grep` 確認 `config.yaml`、`core/interfaces.py`、`prediction/train.py` 不再有 conformal 接線。
- `git diff --check`。
