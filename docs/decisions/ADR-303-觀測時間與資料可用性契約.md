# ADR-303：觀測時間與資料可用性契約

## 背景與問題

第二批審查確認即時時間被改寫為歷史末尾、推論重新擬合特徵、詳情向即時 adapter 查歷史而失敗，以及前端仍在本機假確認／假完成。需要同時對齊資料與執行服務的契約。

## 決策

沿用 ADR-005～010、302，將即時、歷史、Mock 明確分開。每筆站點提供 source、source_timestamp／observed_at、received_at、data_freshness（live/stale/historical/mock）、品質原因；timestamp 相容欄位代表觀測時間，時間統一 ISO8601 含時區，無時區官方 mday 視為 Asia/Taipei。未啟用或非法存量不得進派工池。

即時來源失敗使用同來源最後成功快照並標 stale；沒有快照回 503，不用歷史／Mock 冒充。歷史查詢獨立讀取，失敗在詳情 metadata 表達。正式來源的預覽與確認均拒絕 stale/historical/offline 站點；Mock 模式僅供受控 Demo。

本 ADR 取代 ADR-118 並完整承接其駐點預備車、車隊保留率、緊急警報及其他資源決策；只修訂即時天氣的傳輸、觀測時間、快取與缺值處理。

CWA 即時天氣同樣驗證 HTTPS，沿用 ADR-118 的雙資料集及最近測站，但取代其 verify=False 條款；快取 300 秒並保留觀測時間，缺測／過期值不當作即時特徵。

YouBike 官方 HTTP 驗證 TLS、限制 HTTPS 官方主機、timeout／回應大小及請求頻率，取代 ADR-113 的 verify=False 例外（新 ADR-121 承接其餘條款）。五分鐘更新來源預設 refresh=300 秒、stale=600 秒，失敗重試設短期節流。觀測快照僅保留有界記憶體窗口供 lag，重啟缺資料明確降級；不新增雲端資源或背景常駐服務。

固定 LightGBM／NumPy runtime 依賴，Python 3.12 容器補 OpenMP，SQLite 使用既有單實例架構並掛獨立持久化 volume。API／Pydantic／前端同步；未實作的非 Mock 功能回明確 unavailable，不能假裝成功。

## 理由與判準

保留真實來源與時間、失敗可辨識、沿用已核准框架，以可回歸驗證的服務行為完成第二批整合。

## 考慮過的替代方案

保留靜默 Mock fallback 容易把假數字當正式資料；每次推論重擬合既慢又與訓練不一致。新增雲端資料平台／正式認證非本次必要範圍，維持既有本機 Demo 限制。

## 影響與後果

資料缺失會顯示無預測／過期，部分原先看似可派工的站將被阻擋。多出特徵包及客戶端版本同步成本。正式認證、24 小時排程、多實例及第三批模型／路線修正仍待後續。

## 介面與相容性

保留 station_id 與原本主要欄位，新增來源及預測狀態；確認沿用 ADR-302 草稿契約。模式由設定選擇，歷史和 Mock 仍可明確使用。

## 資安與隱私

後端維持角色檢查，公開來源仍驗證 TLS／型別／大小。無新憑證、真實個資或第三方通知。不新增付費基礎設施。

### 官方 TLS 相容性驗證

2026-09-11 實測 Python 3.14 預設嚴格 RFC 5280 檢查拒絕官方鏈（Missing Subject Key Identifier）。只對固定官方主機使用 Python 3.12 基線相容的 X.509 驗證旗標，保留 CERT_REQUIRED、可信 CA、簽章／期限及 hostname 驗證；不使用 verify=False，也不全域更改 SSL。這降低對舊式憑證格式的嚴格度，官方憑證修復後應移除此相容設定。[Python 官方說明](https://docs.python.org/3/library/ssl.html#ssl.create_default_context)。

## 回復或取代方式

可切回明確 Mock 模式或停用寫入；特徵包須與模型成套回復，不能重新開放靜默假資料。後續改變依新 ADR supersede。

## 驗證方式

pytest 以固定時鐘與離線來源驗證時間／過期／斷線、模型特徵及派工重驗；API 流程測試；前端 transport 測試及 npm run build；容器設定與依賴檢查；git diff --check。實際執行結果另記工作報告。
