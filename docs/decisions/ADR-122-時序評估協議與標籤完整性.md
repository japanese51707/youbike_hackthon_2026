# ADR-122：時序評估協議與標籤完整性

## 背景與問題

第三批審查在 `backend/prediction/feature_pipeline.py` 與 `train.py` 查到四類會讓離線數字失真的問題，且與既有 accepted ADR 的宣告不一致：

1. **折內洩漏**：`run_tuning` 只呼叫一次 `build_training_frame(df, TRAIN_END)`，`station_slot_p50`、`station_turnover`、`attach_profile` 指紋與 ADR-106 介入判定的 `_dmean`／`_dstd`，全部以 1～5 月整段擬合；時序 CV 折 `[1,2,3]→4` 的驗證月份已包含在這些統計裡。ADR-103／104／109／110 都寫了「只用訓練期算」，但實作的「訓練期」是整段而非該折。
2. **跨界標籤**：`is_train` 由輸入時間 `dt` 決定。`target_delta_120` 在 5/31 23:00 的標籤取自 6/1 01:00，訓練樣本的答案落在驗證期內；月份折切分（`dt.month`）有同樣問題。
3. **補值與介入遮罩**：`_forward_fill_grid` 對 `available_bikes` 做 forward fill，補出來的值直接成為 `target_delta_*` 的答案，全程沒有旗標可區分真實觀測與補值。ADR-106 的 `is_rebalancing` 由該列自身 `delta_1step` 判定，訓練只排除起始列，60/90/120 分視野中段發生的調度介入沒有被遮掉。`is_censored` 也只用 `target_delta_30` 判定卻套用到全部視野。
4. **輸出語意**：目標變數是「存量淨變化」。ADR-105 已寫明空站／滿站時該值是被物理邊界壓抑的觀測值，不是真實需求；但 `prediction` 對外欄位命名與規則引擎的 `predicted_at_arrival`／`arrival_by_horizon` 沒有承載這個限制，負向預測容易被當成已證實的缺車需求量。

不修正的後果：離線指標（MAE、覆蓋率、precision／recall）系統性偏樂觀，無法作為上線判準，也無法回答「模型是否真的贏過簡單基準」。

## 決策

沿用 ADR-002、101～105、107～112、121；取代 ADR-106，並完整承接其「調度介入標註只做離線資料清理、上線不即時偵測」的核心決策與離線／線上分離邊界，僅修訂遮罩範圍與擬合窗口。

1. **擬合窗口以 fold 為單位**：`build_training_frame` 接受明確的 `fit_mask`；所有由資料擬合而來的量（`station_slot_p50`、`station_turnover` 與其衍生權重／信心分級、行為指紋、介入判定的同時段 mean／std）只在 `fit_mask` 為真的列上擬合，再 transform 到全表。時序 CV 每一折各自重新擬合，不重用跨折統計。未指定 `fit_mask` 時退回既有 `is_train`，行為與現況相容。
2. **切分依目標時間**：訓練／驗證切分以「標籤的目標時間 `dt + horizon`」是否落在訓練期決定，每個視野各有一個切分旗標；輸入時間在訓練期但目標時間跨入驗證期的列，不得進入訓練集。折切分同樣依目標時間。
3. **補值可辨識**：forward fill 產生的列標記 `is_imputed`；補值列不得作為評估的答案，主指標只用真實觀測列計算，補值列另行分開報告。補值列是否進訓練由開關決定，預設排除。
4. **遮罩涵蓋整個視野**：`is_censored` 與調度介入遮罩改為逐視野計算——第 `t` 列對視野 `h` 的標籤，只要 `t+1..t+h` 任一格被判定為調度介入即排除；截斷判定使用該視野自身的目標與當時的空／滿狀態。
5. **輸出語意明示**：模型輸出一律標示為「存量淨變化（受供給限制的觀測量）」。預測回應與規則引擎輸出新增語意欄位，標明該值是淨變化推算的到達存量，而非未受供給限制的需求量；截斷情境沿用 ADR-105 的 `is_censored_demand` 表達「需求被邊界壓抑」，不得把負向預測直接當成已證實的缺車台數。ADR-105 列為選配的需求插補，本 ADR 不啟用。
6. **不覆蓋現行上線模型**：本 ADR 產生的候選模型與特徵包寫入獨立目錄，`backend/prediction/_models/` 不動，serving 仍依 ADR-121 成套載入既有版本。是否換版另以工作紀錄與 owner 決定為準。
7. **評估必須有基準**：各視野同時報 MAE、P10–P90 覆蓋率、分位數交叉率、空／滿事件 precision／recall，並與 seasonal naive 及 persistence（Δ=0）兩個簡單基準對照；分區間（健康／接近空／已空）與新舊站分報沿用 ADR-105／108。

## 理由與判準

- **正確性優先於數字好看**：修正後指標預期變差，那才是可作為決策依據的誠實基線。
- **與既有宣告一致**：ADR-103／104／109／110 本來就要求防洩漏，本 ADR 是落實而非改方向；只有遮罩範圍與切分定義是真正的變更，故以取代 ADR-106 的方式記錄。
- **可逆**：`fit_mask` 預設相容、候選模型不覆蓋現行模型，撤回成本低。
- **不擴大範圍**：不新增資料源、不新增依賴、不改 serving 載入方式。

## 考慮過的替代方案

### 方案 A：只修 CV 折，不改切分與遮罩

- 優點：改動最小。
- 缺點：跨界標籤與視野中段介入仍會讓 60～120 分視野的數字偏樂觀，問題只被推遲。
- 未採用原因：無法得到可信的多視野基線。

### 方案 B：直接重訓並覆蓋上線模型

- 優點：一次到位。
- 缺點：在指標尚未驗證前替換 serving 模型，違反 ADR-121 成套驗證與可回復原則。
- 未採用原因：owner 明確要求不直接覆蓋目前模型。

### 方案 C：啟用 ADR-105 的需求插補還原真實需求

- 優點：能回答「真實缺口」而非僅淨變化。
- 缺點：ADR-105 已列為選配、成本高，且需要新的假設與驗證。
- 未採用原因：超出第三批範圍，維持為未解決項。

## 影響與後果

### 正面

- 離線指標可作為上線判準；多視野數字不再被跨界標籤與補值答案污染。
- 調度介入與截斷樣本的處理與視野一致，訓練集定義可稽核。
- 對外輸出語意明確，降低把淨變化當成需求量的誤用風險。

### 負面與代價

- 修正後 MAE／覆蓋率／precision／recall 預期下降，需重新建立基線敘事。
- 每折重新擬合使 CV 成本上升。
- `is_imputed`、逐視野遮罩使特徵表欄位變多，記憶體與執行時間增加。

### 尚未解決

- 真實需求插補（ADR-105 選配）未做。
- 是否以候選模型替換上線模型，待指標出來後由 owner 決定。
- conformal 校準、跨站共享資訊的模型結構調整不在本批。

## 介面與相容性

`build_training_frame` 新增 `fit_mask`、`with_imputed` 等關鍵字參數，預設值維持既有行為；輸出 frame 新增 `is_imputed`、逐視野的 `is_train_{mins}`、`is_censored_{mins}`、`is_rebalancing_{mins}` 欄位，既有欄位保留。預測回應與規則引擎輸出新增語意欄位，既有欄位名稱與型別不變，前端不需同步即可運作。`backend/prediction/_models/` 與 `serving_features.json` 不變更，ADR-121 的成套驗證不受影響。

## 資安與隱私

無。本 ADR 只處理離線訓練與評估流程，不新增資料源、外部請求、憑證或個資，不改變 API 授權。

## 回復或取代方式

移除 `fit_mask` 呼叫端即可回到舊行為；候選模型目錄可直接刪除而不影響 serving。若要改變評估協議，以新 ADR supersede 本 ADR，不改寫本檔決策內容。ADR-106 保留為 superseded，其離線／線上分離條款由本 ADR 承接。

## 驗證方式

- 小型固定資料的 pytest：手工序列刻意植入跨界標籤、補值段、視野中段介入、空站截斷與跨折統計洩漏；修正前應失敗、修正後通過。
- 子集離線評估：本機 1～6 月 Parquet 取站點子集，報修正前後各視野 MAE、覆蓋率、交叉率、空／滿事件 precision／recall，對照 seasonal naive 與 persistence 基準。
- 跑最窄相關 pytest 與 `git diff --check`；不 commit／push。
