# ADR-115：動態目標水位與補／抽車量計算

## 背景與問題

規則引擎判斷「要不要調度、補還是取」後，還要算「補／抽幾台」。現況（rule_engine.evaluate_station）：

```python
target_available = total * float(target["預設借用率百分比"]) / 100   # 固定 50%
quantity = round(target_available - available)   # 補到固定 50% 水位
```

問題：**目標水位寫死 50%，沒考慮該站後續時段的流動性。**

- 捷運站早尖峰（後續狂流出）：補到 50% 撐不了多久又空，等於白跑。
- 住宅區晚上（後續狂流入）：抽到 50% 之後又滿，又要再來一趟。

owner 要求：補到「能撐過後續高風險時段」的水位；過了尖峰後，因後續流量趨緩，
目標水位會自然回落到接近 50/50。這需要把「後續預測流量」納入補／抽車量的計算。

我們已有現成的模型輸出可用（ADR-113）：每站 4 視野（30/60/90/120 分）× P10/P50/P90 的累積 Δ 區間。
**區間寬度本身就是流動性的表現**（波動大的站區間寬），這正是動態目標水位需要的資訊。

## 決策（proposed，待 owner 核准）

補／抽車量的「目標水位」由固定 50% 改為**動態計算**：補到能吸收「後續視野內最悲觀淨流量」的水位，
再用 80/20 護欄夾住。

### 一、視野

用 **60 分累積 Δ**（`目標水位_視野分鐘: 60`）。
- 理由：響應時間 30 分 + 撐一段；90 分不確定性太高，且可能已跨過尖峰而失真（owner 決定）。
- 取「撐到視野（60 分）的累積 Δ」，不取「各視野最極端值」（後者過度保守，會把 120 分才發生、
  但那時可能已下一輪調度的流量也算進來）。

### 二、安全緩衝底線改「比例」（隨站大小縮放）

現況 `安全緩衝_台數: 2` 是固定絕對值 → 大站只留 2 台緩衝，風險過大。
改為 **`安全緩衝_比例: 0.12`**（柱數的 12%）：

- 60 柱大站 → 底線 ≈ 7 台（自動放大）
- 20 柱小站 → 底線 ≈ 2 台（維持合理）

保留 `安全緩衝_台數` 作為「無柱數資料時」的絕對值 fallback。

★注意：本 ADR 的「比例緩衝」用於**補／抽車量計算（補到哪）**；
ADR-111 的觸發判斷（`arrival <= 安全緩衝_台數`，判斷要不要調度）**不在本 ADR 變更範圍**，維持原邏輯。
兩者是不同決策點（一個判「要不要調」、一個判「調多少」），刻意分開。

### 三、補車量公式（防空，用 P10 悲觀）

```
安全底線     = 柱數 × 安全緩衝_比例
後續最大流出 = |min(0, 累積Δ_P10@60分)|                 # 悲觀情境的淨流出
目標存量_raw = 安全底線 + 後續最大流出
目標存量     = clip(目標存量_raw, 柱數×下限, 柱數×上限)   # 80/20 護欄
補車量       = max(0, round(目標存量 − 現況))            # 再受車輛載運量上限約束
```

### 四、抽車量公式（防滿，用 P90 樂觀，對稱）

```
安全底線_空位 = 柱數 × 安全緩衝_比例
後續最大流入  = max(0, 累積Δ_P90@60分)                   # 樂觀情境的淨流入
目標空位_raw  = 安全底線_空位 + 後續最大流入
目標存量_raw  = 柱數 − 目標空位_raw
目標存量      = clip(目標存量_raw, 柱數×下限, 柱數×上限)
抽車量        = max(0, round(現況 − 目標存量))
```

### 五、80/20 護欄（可配置）

```
安全水位_下限: 0.20   # 補完存量不低於柱數 20%
安全水位_上限: 0.80   # 補完存量不高於柱數 80%
```

- 補車永不超過 80% 滿（留空位吸收臨時流入）；抽車永不低於 20%（不抽到接近空）。
- 也保護「模型預測失準時不補過頭」。owner：80/20 為預設，可配置後續調整。

### 六、累積 Δ 怎麼從模型輸出取

模型輸出的是「到達存量」區間（現況 + Δ）。累積 Δ = 到達存量 − 現況：

```
累積Δ_P10@60 = interval@60.raw_lower_bound − 現況     # 用 raw（照實不夾，ADR-111）
累積Δ_P90@60 = interval@60.raw_upper_bound − 現況
```

多視野區間由 predict_multi 提供（ADR-113）；取 60 分視野那組。

### 退場／降級
- 無 multi（無 4 視野）或無 60 分視野：退回用單視野 prediction 的下界/上界估累積 Δ。
- 完全無預測（降級）：退回固定目標水位（`target.預設借用率百分比`），維持現況行為不中斷。

### 不改
- ADR-111 觸發判斷（要不要調度、三層 censored/warning/normal）。
- ADR-112 緊急度分數。
- ADR-113 預測模型與區間產出。
- 車輛載運量上限約束（ADR-114，quantity 仍 ≤ 車容量）。

## 理由與判準

- **對準真實營運**：補到「撐過後續高風險時段」才是有效調度，減少白跑與重複調度。
- **善用既有模型輸出**：直接用 ADR-113 的 P10/P90 區間，流動性天然納入（區間寬 → 留更多緩衝），
  不需新資料或新模型。符合 steering §5（AI 只估計，規則引擎用區間下/上界決策）。
- **規模自適應**：緩衝用比例，大站小站都合理（解決固定 2 台對大站風險過大）。
- **自然回落**：離峰時後續流量趨緩 → 後續最大流出/流入 ≈ 0 → 目標存量回落到接近安全底線水位，
  貼近 owner 要的「過了尖峰接近 50/50」。
- **參數外部化**：緩衝比例、80/20 護欄、視野分鐘全進 config（steering §3）。

### 情境驗證（設計階段手算，實作後以測試覆蓋）

| 情境 | 柱數 | 現況 | 累積Δ@60 | 安全底線(12%) | 目標存量(夾20~80%) | 動作 |
|------|------|------|---------|--------------|-------------------|------|
| 捷運站早尖峰 | 40 | 3 | P10 −18 | 4.8 | 4.8+18=22.8 →[8,32]→ 22.8 | 補 20 |
| 同站中午離峰 | 40 | 15 | P10 −3 | 4.8 | 4.8+3=7.8 → 現況15已高於 | 不補 |
| 住宅區晚上 | 40 | 35 | P90 +12 | 4.8 | 40−(4.8+12)=23.2 →[8,32]→ 23.2 | 抽 12 |

離峰情境驗證「過了尖峰回落到中間、甚至不需調度」。

## 考慮過的替代方案

### 維持固定 50% 目標水位
- 缺點：不看後續流動性，尖峰補不夠、離峰可能補過頭；白跑與重複調度。未採用（正是本 ADR 要解的）。

### 用歷史「站×hour 周轉量」定目標水位（做法 B）
- 優點：比固定值好，周轉量高的站補多點。
- 缺點：周轉量是歷史平均，非當下預測；不如直接用模型的當下 P10/P90 精準。未採用（但周轉量已用於緊急度 ADR-112）。

### 最佳化「下次調度前不出事」機率（做法 C）
- 優點：最精準。
- 缺點：對黑客松過重、可解釋性差。未採用（先用做法 A，未來可升級）。

### 安全緩衝用固定台數
- 缺點：大站風險過大（owner 指出）。未採用，改比例。

### 目標水位視野用 90 分
- 缺點：不確定性高、可能已跨過尖峰失真（owner 決定用 60）。未採用。

## 影響與後果

### 正面
- 補／抽車量貼近真實需求；尖峰補得夠、離峰不過頭；減少重複調度。
- 緩衝隨站大小自適應；護欄防過頭。

### 負面與代價
- rule_engine 補／抽車量計算段改寫；config 加 4 參數、改緩衝為比例。
- 依賴 multi（4 視野）品質；無 multi 時走降級（行為與現況一致）。

### 尚未解決
- 「後續最大流出/流入」目前取單一 60 分視野；未來可評估加權多視野。
- 護欄 80/20 的最適值待現場資料回饋調整（已配置化）。

## 介面與相容性

- 不改 evaluate_station 對外簽名與輸出 dict 欄位（quantity 語意不變，只是算法變準）。
- 不改 predictor / urgency / dispatcher 介面。
- config 新增 `安全緩衝_比例`、`安全水位_下限`、`安全水位_上限`、`目標水位_視野分鐘`；
  保留 `安全緩衝_台數`（觸發判斷仍用 + 比例的 fallback）、`target.預設借用率百分比`（降級 fallback）。

## 資安與隱私

- 無（純決策邏輯與參數，無對外通訊、無 PII）。

## 回復或取代方式

- 移除新參數、還原補／抽車量計算段即回復固定 50%；改方向以新 ADR supersede。

## 驗證方式

- 單元測試：三情境（尖峰補足/離峰不補/晚間抽車）數量正確；80/20 護欄邊界；比例緩衝大小站；
  無 multi 降級退回固定水位；quantity ≤ 車容量。
- 跑既有 test_rule_engine 全過（觸發判斷不受影響）。
- 全套件不破壞。
