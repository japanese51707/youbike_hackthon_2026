# ADR-204：數位孿生戰情室設計語言與自帶暗色底圖

## 背景與問題

ADR-202 已定案三頁共用 MapLibre／Deck.gl／OpenFreeMap 地圖與 no-basemap 降級，並完成實作（commit `d1fdb16`）。但目前視覺仍是預設亮色 OpenFreeMap liberty 與一般 Ant Design 樣式，缺少「工業級數位孿生 / 智慧調度戰情室」該有的視覺與資訊密度：暗色骨架地圖、多維度資產編碼、圖層控制、時空異常視覺化與調度決策面板。

owner 已明確選擇：
1. 底圖採 **(B) 自帶一份暗色 style JSON**（tile／glyph／sprite 仍指向 OpenFreeMap 同源），而非僅客戶端重新著色。
2. 進階視覺層要**全部**做：ArcLayer、Hexagon 密度基底、Voronoi 勢力範圍／熱區。
3. 等寬字體採**系統等寬字體堆疊**，不引入外部字型資產。

選項 1 會改變 ADR-202「host style 固定為 `.../styles/liberty`」這條核心決策，依治理規則不可改寫 ADR-202，必須由本 ADR supersede 並承接其餘未變決策。這也是一項跨三頁共用的設計語言，屬於需要記錄的共用慣例。

## 決策

### 一、底圖 style 來源（變更 ADR-202）

- 底圖改用**專案自帶（bundle 於前端）的暗色 MapLibre style JSON**，取代原本固定載入的遠端 `https://tiles.openfreemap.org/styles/liberty`。
- 該自帶 style 的資料來源（vector tiles、glyphs、sprite、raster）**仍限定為 OpenFreeMap 同源 `https://tiles.openfreemap.org`**；origin allowlist、`transformRequest` 檢查與出向信任邊界維持 ADR-202 不變。
- style 的背景、道路、水域、地名等 paint 以深藍灰（基底 `#0F172A`／`#0B0F19`）為主，移除無關 POI 標籤，讓上層 Deck.gl 亮色資料元素突出。
- 仍保留 OpenFreeMap／OpenMapTiles／OpenStreetMap 要求的 attribution，且在 `loading`／`ready`／`no-basemap`／`map-unavailable` 所有狀態持續可見。

### 二、設計語言（跨三頁共用慣例）

- 基礎底色深藍灰（Slate-900 系），透過 Ant Design `ConfigProvider` theme token 集中設定主色、圓角、背景、文字色，不逐頁硬寫色碼。
- 數據、時間戳記、預測百分比等使用**系統等寬字體堆疊**（`ui-monospace, SFMono-Regular, "JetBrains Mono", Menlo, Consolas, monospace`），不新增字型套件、不對外抓取字型（避免額外出向請求）。
- 站點採多維度資產編碼：環形進度環（弧長＝可借比例，顏色＝預測風險綠→橘→紅），hover 顯示微型火花圖與信賴區間。
- 地圖提供圖層控制：即時狀態 / 預測流向 / 調度建議三層可切換。
- 右側調度戰情面板：缺口排行榜（點擊 FlyTo）與調度建議卡片。

### 三、新增前端視覺依賴（精確釘選）

- `@deck.gl/aggregation-layers`（HexagonLayer 密度基底），與既有 `@deck.gl/*` 同一 minor 版本線。
- `d3-delaunay`（計算 Voronoi 多邊形，交由既有 `@deck.gl/layers` PolygonLayer 繪製）。
- ArcLayer 使用既有 `@deck.gl/layers`，不新增依賴。
- 全部採精確版本並提交 lockfile（沿用 ADR-008／ADR-201 釘選原則）。

### 四、承接 ADR-202 未變的決策

- 三頁共用單一 MapLibre／Deck.gl 模組；Deck 資料層與控制面板不綁底圖生命週期。
- 不使用任何需帳務／信用卡／API key／按量計費／可能超額扣款的地圖 provider 或 API。
- 底圖 style／tile／glyph／sprite 一律視為不可信第三方輸入；限制來源、處理載入錯誤、逾時與斷網，切換 `no-basemap` 且資料層與控制面板持續運作。
- 不得把任務、預測、operator／task 識別碼、使用者資料或憑證放入底圖請求的 URL／query／header。
- Google Maps plain navigation URL 維持既有契約，不加入計費 API 或 key。
- 完整沿用 ADR-201／ADR-202 承接的 React／Vite／JSX／Router／Ant Design／ECharts／Mock-first adapter／三路由決策。

### 五、與 ADR-203 的關係（不變更）

- 本 ADR 不改 ADR-203：Past／Live／Predict 仍是 frontend-local mock、固定 +30／+60、缺值顯示不可用、不插值、不混用 dynamic ETA。
- 所有新視覺（火花圖 CI、Voronoi 高負載熱區、預測流向粒子、調度建議數字）只能來自既有 frontend-local mock；無對應資料時顯示「不可用」，不得捏造模型輸出或不確定區間。
- 固定 +30／+60 展示資料與新視覺一律不得進入派遣確認、任務建立或其他真實世界操作 payload；調度卡片按鈕維持既有 in-memory「預覽→確認」閘門與 `Mock Demo` 標示。

## 理由與判準

- 自帶暗色 style 讓數位孿生的「過濾噪音、直擊本質」視覺成立，且資料來源仍鎖 OpenFreeMap 同源，維持零計費、無 key 與出向邊界不變。
- 設計語言集中於 theme token 與共用地圖模組，避免三頁各自硬寫樣式造成不一致與難維護。
- 系統等寬字體堆疊零依賴、零額外出向請求，符合資安與交付速度。
- 新增視覺依賴限定在前端呈現層，不影響 backend／prediction／共同契約。

## 考慮過的替代方案

### 方案 A：僅客戶端重新著色 liberty（不改 ADR-202）

- 優點：完全不動 ADR-202，最小治理成本。
- 缺點：受 liberty 原始圖層結構限制，暗色化程度與一致性較差，難以完全移除噪音標籤。
- 未採用原因：owner 明確選擇 (B) 自帶 style 以取得完整暗色控制。

### 方案 B：自帶暗色 style JSON（本 ADR 採用）

- 優點：對背景／道路／標籤有完整控制，數位孿生視覺最完整；資料仍鎖 OpenFreeMap 同源。
- 缺點：需維護一份 style JSON，並改寫 ADR-202 的 style 來源條款。
- 未採用原因：無（採用）。

### 方案 C：改用商業暗色底圖 provider

- 優點：現成高品質暗色樣式。
- 缺點：需 API key／帳務／可能計費。
- 未採用原因：違反 ADR-202 承接的零計費、無 key 硬性限制。

## 影響與後果

### 正面

- 三頁獲得一致的戰情室視覺與資訊密度，Demo 專業度提升。
- 底圖來源仍鎖 OpenFreeMap 同源，出向安全與零計費不變。
- 主題集中於 token，後續調色不需逐頁改。

### 負面與代價

- 需維護一份自帶暗色 style JSON，OpenFreeMap 若變更 tile／sprite／glyph 路徑需同步。
- 新增 `@deck.gl/aggregation-layers`、`d3-delaunay` 會增加 bundle 與 WebGL 資源負擔。
- Voronoi／Hexagon／Arc 在低階裝置的效能需驗證。

### 尚未解決

- 後端真實預測的更新頻率與 horizon 仍未定（見 ADR-203 待決策）；時序軸與動畫先做成設定驅動，待顆粒度定案再調預設值。
- 自帶 style 的實際色票與圖層取捨細節於實作時定案。

## 介面與相容性

- 頁面仍只透過 hooks 與 domain API modules 取資料；Mock adapter／未來 FastAPI adapter 邊界不變。
- 共用地圖模組對外介面（底圖狀態、資料圖層、選取事件、viewport、no-basemap 狀態）維持相容；新增圖層控制與面板為前端呈現層。
- 不修改 backend、prediction、共同 API、Schema、Pydantic 模型或 dispatch payload。

## 資安與隱私

- 自帶 style 的所有遠端資源仍限定 OpenFreeMap 同源，維持 origin allowlist 與 `transformRequest`。
- 不新增外部字型或分析追蹤等出向請求。
- 底圖請求不得攜帶任務、預測、使用者或憑證資料；attribution 持續可見。
- 新視覺資料一律來自 frontend-local mock，不外流至第三方。

## 回復或取代方式

- 可將底圖 style 切回遠端 liberty 或 local empty style 以撤回暗色 style；資料層與控制面板應維持可用。
- 可移除新增視覺依賴與圖層回到 ADR-202 狀態。
- 若未來要改地圖框架、provider 或設計方向，建立新 ADR supersede 本決策，不改寫 ADR-202 或本 ADR 歷史。

## 驗證方式

- 三頁顯示自帶暗色底圖，且 attribution 可見；網路檢查證明底圖請求皆為 OpenFreeMap 同源、無 API key、無任務／預測／使用者資料。
- 阻擋 style／tile 或斷網時顯示明確錯誤並進入 no-basemap，Deck 資料層、清單與控制面板仍可用。
- 火花圖 CI、Voronoi 熱區、預測流向與調度數字在 mock 缺值時顯示「不可用」，不插值、不捏造。
- 前端操作檢查證明固定 +30／+60 與新視覺資料不進入派遣／任務 payload；卡片維持預覽→確認閘門與 Mock Demo 標示。
- `npm run build` 通過並產生 lockfile；三頁 smoke test 通過。
