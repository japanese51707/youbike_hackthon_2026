# ADR-112：緊急度分數計算公式

## 背景與問題

ADR-111 把站點分三層（censored 截斷／warning 警示／normal），並定「緊急度分數在 urgency 層算，
規則引擎只給層級」。但**緊急度分數的實際公式尚未定義**——dispatcher 需要一個 0~100 分數來排序
（現行 MockUrgencyCalculator 只是啟發式佔位）。

owner 已提出緊急度應考慮的因素（本 ADR 將其形式化）。不做決策的後果：排序靠佔位啟發式，
無法反映「哪一站真的最該先派車」。

## 決策（proposed，待 owner 核准）

緊急度分數 = **層級打底分 + 層級內排序分**，輸出 0~100，越高越急。

### 分數結構（分層打底，確保 censored 一定 > warning）

| 層級 | 打底分區間 | 說明 |
|------|-----------|------|
| censored（截斷，穿透邊界） | **70~100** | 保證最高緊急，一定排在 warning 之前 |
| warning（警示，快空/快滿未穿透） | **30~69** | 需調度但非最急 |
| normal | 不進調度清單（無分數） | — |

層級內用下列因素算「排序分」，落在該層級的區間內：

### 五項輸入因素（owner 定 + 補充）

1. **穿透/接近時機**（breach_horizon_min 或最接近觸發的視野）：
   30 分 > 60 > 90 > 120。越早出事越急。→ 時機分（早=高）。
2. **嚴重層級**：已由「層級打底分」表達（censored > warning）。
3. **該時段人流**（owner 定，前後 1 小時）：該站 × 該 hour 的**訓練期歷史平均周轉量**
   （周轉量 = |Δ可借車數| 絕對變化累加；6:30 看 6:00~7:00）。越高越急（缺車影響越多人）。
   → 人流分（正規化到 0~1，用該站在全市的相對百分位或對數壓縮）。
   ★資料確認：可借車數為 Int32 整數（實測 0% 非整數），周轉量計算無小數誤判風險
   （借用率/空位率才是 Float，本公式不用）。★防洩漏：人流統計只用訓練期算。
4. **當下是否已全空/全滿**（現況 available==0 或 ==total）：是→加成（已經在出事，不只是預測）。
5. **穿透幅度**（censored 專屬）：缺口深淺 = |raw_lower|（缺車）或 raw_upper−total（爆滿）。
   越深越急。→ 幅度分（僅 censored 層用）。

### 公式（初版，權重待實驗/校準）

```
score = 層級打底分 + 層級內排序分（落在該層區間）

censored 層（打底 70）：
  排序分 = 30 × [ 0.35·時機分 + 0.20·人流分 + 0.25·當下空滿加成 + 0.20·幅度分 ]
  （owner 定初版權重 時機0.35/人流0.20/當下0.25/幅度0.20，和=1）

warning 層（打底 30）：
  排序分 = 39 × [ w1·時機分 + w3·人流分 + w4·當下空滿加成 ]
  （幅度分不適用；由 censored 權重去掉幅度後正規化：時機0.35/人流0.20/當下0.25 → /0.80
   = 時機0.4375/人流0.25/當下0.3125）
```

初版權重為 owner 定起始值（比照 ADR-110 誠實標記「未調校」），可 config 調、待實際排序效果校準。

### 職責與不改

- 緊急度分數在 **urgency 層**算（實作 UrgencyCalculator），規則引擎只給層級與旗標（ADR-111/004）。
- confidence_tier（流量信心，ADR-109）**不進緊急度分數**（守 ADR-104：流量是排序 tie-break 非緊急依據），
  僅在 dispatcher 同分時當次要排序鍵。
- 不改 PredictionInterval、不改 API 契約主體。

## 理由與判準

- **分層打底**保證「截斷一定比警示急」，符合 owner「穿透邊界最高緊急」的鐵則，不會被人流等因素翻轉層級。
- **層級內多因素**讓同層站點有合理先後（早出事、人流大、已空、缺口深 → 先派）。
- **人流用歷史周轉**量的是實際活躍度，比容量大小更能反映「這站空了影響多少人」。
- **可解釋/可校準**：每項因素可拆解說明，權重 config 可調。

## 考慮過的替代方案

### 方案 A：單一線性加權（不分層）
- 缺點：人流極大的 warning 站可能分數超過 censored 站，翻轉層級，違反 owner 鐵則。
- 未採用：必須保證 censored > warning。

### 方案 B：只用「到達存量離邊界距離」單因素
- 缺點：忽略時段人流（冷門站空了 vs 熱門站空了同分），排序失真。
- 未採用：owner 明確要人流納入。

## 影響與後果

### 正面
- dispatcher 有合理的排序依據，最該派車的站排最前。
- 分數可解釋，簡報/調度員可理解「為什麼這站最急」。

### 負面與代價
- 需新增「站×hour 訓練期平均周轉量」統計（類似行為指紋，防洩漏）。
- 權重為未調校起始值，排序效果待校準（可能需 F-09 決策層 precision/recall 驗證）。

### 尚未解決
- 各項權重（w1/w3/w4/w5）的最佳值待校準。
- 人流分的正規化方式（全市百分位 vs 對數壓縮）待實作時定。
- 多視野時機分怎麼取（最早穿透視野）與 ADR-111 一致。

## 介面與相容性

- 實作 `UrgencyCalculator.calc_urgency`（interfaces.py 已有 Protocol），取代 MockUrgencyCalculator 啟發式。
- 需要「站×hour 訓練期平均周轉量」統計來源（features 層新增，或預算好的表）。
- dispatcher 既有排序（priority_score 降序 + confidence_tier tie-break）不變，只是分數來源變真實公式。

## 資安與隱私

- 無（純計分邏輯與站點行為統計）。

## 回復或取代方式

- 公式與權重為 config，可還原為佔位啟發式；設計變更以新 ADR supersede。

## 驗證方式

- 單元測試：censored 站分數必 > warning 站（層級不被翻轉）；同層內早出事/人流大/已空/缺口深者分數較高。
- 抽查排序：已知熱門常空站（如板橋核心）緊急度應偏高。
- 確認 confidence_tier 未進分數（守 ADR-104）。
