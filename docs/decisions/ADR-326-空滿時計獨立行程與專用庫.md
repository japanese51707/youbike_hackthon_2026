# ADR-326：空滿時計獨立行程與專用庫

> 原於 `feat/officer-page` 編為 ADR-320；合進 `main` 時讓號至 326。

## 背景與問題

ADR-325 把空／滿時計輪詢掛在 FastAPI lifespan 的背景 thread。本機 `youbike-local-dev` 用 `uvicorn --reload`：改檔就重啟行程，thread 死、時計中斷。主庫路徑若依 PROJECT_ROOT 解析，容器把 `backend/` 掛成 `/app` 時會落到不在 volume 上的 `/backend/data/youbike.db`，重開 container 也丟。

不做決策的後後果：本機盯盤時計仍跟開發重載綁在一起，不是跟站況綁在一起。

## 決策

1. **時計另存** `service_clock.db`，不寫進 `youbike.db`。進行中時計只會因站況恢復或空↔滿而關，不會被主庫重置／seed 清掉。
2. **獨立 worker** `backend/tools/service_clock_worker.py`：無限迴圈 `poll_once`，不經 uvicorn。本機另開 `youbike-clock-worker` 容器，不要 `--reload`。
3. **路徑釘在 backend 套件旁**（容器內 `/app/data/service_clock.db` = host `backend/data/`，已 gitignore）。`YOUBIKE_CLOCK_DB_PATH` 可覆寫；若已設檔案型 `YOUBIKE_DB_PATH`，預設放同目錄 `service_clock.db`（compose／ECS runtime volume）。
4. **測試記憶體模式**（`YOUBIKE_DB_PATH=:memory:`）仍與主連線共用，不另開檔。
5. **雲端單 ECS task** 維持 ADR-325 in-app thread（無 sidecar）。設 `SERVICE_CLOCK_EXTERNAL=1` 或 `service_problems.in_app: false` 時 API 不開 thread，避免與 worker 雙寫。
6. 仍無法回補「啟動前就已空／滿多久」；第一次看到才開案。

## 理由與判準

- **正確性**：時計生命週期跟收集行程走，不跟熱重載走。
- **可逆**：關掉 worker、清 `SERVICE_CLOCK_EXTERNAL` 即回到 in-app。
- **不改契約**：`GET /api/v1/service-problems` 不變；只換寫入位置與誰負責輪詢。

## 考慮過的替代方案

### 只把 in-app thread 寫進 volume 上的主庫

- 優點：少一個行程。
- 缺點：`--reload` 仍殺掉收集；主庫重置會一起清時計。
- 未採用原因：owner 要「另開、持續跑、不被覆蓋」。

### ECS 也拆 sidecar

- 優點：雲端與本機對稱。
- 缺點：改 task 定義，超出本機問題。
- 未採用原因：雲端無 `--reload`，in-app 足夠；之後若要拆再用新 ADR。

## 影響與後果

### 正面

- 本機改後端不會中斷空滿時計。
- 時計檔在 bind mount 上，重開 API container 仍在。

### 負面與代價

- 本機多一個容器；worker 與 API 同時開時可能多打一次官方站況（邏輯冪等，不重置 `opened_at`）。
- 既有寫在 `youbike.db` 的時計不自動遷移。

### 尚未解決

- 官方歷史「這站其實空了三小時」仍無法回補。
- 雲端 task 重啟仍有空窗。

## 介面與相容性

- 新檔：`backend/db/clock_connection.py`、`backend/tools/service_clock_worker.py`。
- 環境變數：`YOUBIKE_CLOCK_DB_PATH`、`SERVICE_CLOCK_EXTERNAL`。
- `config.yaml` `service_problems.in_app`（預設 true）。
- 表結構與 API 不變。

## 資安與隱私

- 無新對外寫入；仍只存站名與行政區。worker 不需 AWS 金鑰（官方站況 HTTPS）。

## 回復或取代方式

- 以新 ADR supersede。刪 worker、還原 repo 用 `get_connection()` 即退回 ADR-325。

## 驗證方式

- worker log 出現啟動與寫入路徑；改後端觸發 `--reload` 後 worker 仍活著。
- `backend/data/service_clock.db` 有進行中列；主庫沒有同表新寫入（本機檔案模式）。
- `SERVICE_CLOCK_EXTERNAL=1` 時 API 不開 in-app thread。
