# ADR-309：緊急調度案件的升級追蹤與關案條件

## 背景與問題

題目點名「現行機關系統無警示通知功能」，ADR-118 與現行 `alert_service` 已能產生分級警示，
但**警示只會出現，不會追蹤**。owner 要的是：跳出來之後沒人處理，30 分鐘要再提示、
45 分鐘要再提示並電話聯絡。

把計時器直接加在現行警示上做不到，有三個結構性原因（讀 `core/alert_service.py`、
`db/alerts_repo.py` 確認）：

1. **警示是每次查詢即時重算的**。`GET /alerts` 會掃站況重新產生；
   `resolve_stale_by_station()` 在站況恢復、或訊息與現況矛盾時直接 `DELETE` 整筆再重建。
   `alert_id` 會換、`triggered_at` 會歸零。
2. **去重只看未讀警示**（`unacked_station_levels()`）。只要有人按一次「標記已讀」，
   下一輪同站同級就會產生一筆全新警示，等待時間從 0 重算。
3. **「已讀」目前等於消音，但它不代表「已處理」**。若升級以已讀為準，
   實務上的均衡是「大家按已讀讓它安靜」，30/45 分鐘的升級永遠不會觸發。

也就是說，現行資料結構裡沒有任何一個欄位能誠實回答「這個站已經沒人管幾分鐘了」。

## 決策

沿用 ADR-111（三層觸發）、ADR-118（緊急救火）、ADR-302（派工確認與結案）、
ADR-206（調度面板資訊架構）；不取代任何 ADR。

### 1. 升級時鐘掛在「案件」上，不掛在警示上

新增 `alert_cases`：**以站為單位**的緊急調度案件。`opened_at` 在該站第一次需要緊急調度時
寫入，之後警示怎麼刪除重建都不影響它。警示仍維持現行「即時重算」語意不變——
案件是疊在警示之上的追蹤層，不改警示本身。

同一站同時間最多只有一個未結案案件（partial unique index）。

### 2. 關案只認確定性事件，不認按鈕

案件只有兩種關法，都由系統判定，不由人宣告：

| close_reason | 條件 |
|---|---|
| `dispatched` | 有一張**未結案**的派工任務，其路線涵蓋該站 |
| `recovered` | 該站本輪不再需要緊急警示（站況已恢復） |

**「已讀」不關案、不重置時鐘**，只把案件靜音 `config.escalation.靜音分鐘` 分鐘。
靜音期間不跳橫幅與彈窗，時鐘照走；靜音到期若仍未派工，回到當時應在的階段。

這條是本 ADR 的核心：升級機制若能被一個按鈕解除，它就不是追蹤，只是提醒。

### 3. 升級階段由設定決定，不寫死

`config.escalation.階段` 為分鐘數陣列，預設 `[30, 45]`：

| 階段 | 條件 | 前端行為 |
|---|---|---|
| L0 開案 | 0 分 | 卡片標紅，顯示已等待時間 |
| L1 提醒 | 等待 ≥ 階段[0] | 跨頁常駐橫幅 + 提示音 |
| L2 電話 | 等待 ≥ 階段[1] | 強制彈窗（不可點外關閉），必須選一個出口 |

階段一律由 `now − opened_at` 與設定值比較得出，是確定性規則，不經任何模型。
`highest_stage` 記錄曾達到的最高階段，供稽核與「已提示過」判斷。

### 4. L2 的三個出口都留稽核軌跡

新增 `alert_case_actions`，每一次人為動作都寫一筆（誰、幾點、做了什麼、備註）：

- `dispatch`：轉去組單（實際關案仍由第 2 點的派工判定，不由這個動作關）
- `called`：已電話聯絡，必填聯絡對象；靜音後仍未派工會再跳
- `deferred`：延後處理，**必填原因**

電話聯絡對象來自 `config.escalation.值班聯絡`（依行政區），前端以 `tel:` 連結呈現。
本批**不接簡訊／LINE 等外部推播**——推播是出向行為，需另立出向資安評估（steering §11）。

### 5. 時間一律由後端換算

API 回 `opened_at`、`waited_minutes`、`stage`、`next_stage_at`，前端**不自己累加計時**。
重整頁面、換一台電腦、調度員與管理後台三邊看到的數字必須一致，這是稽核前提。

## 後果

- 好處：「沒人管幾分鐘」變成可查詢、可稽核的事實；升級無法被按鈕解除；
  調度員與管理後台看到同一份真相。
- 代價：多一張表與一個同步步驟（`GET /alerts/escalations` 時順帶開關案），
  與現行警示同樣是「查詢時即時同步」，沒有常駐排程（與 ADR-304 §5 一致，
  常駐排程另案）。
- 風險：若前端輪詢間隔過長，升級提示會延遲到下一次輪詢。預設 30 秒，
  相對 30/45 分鐘的階段可忽略。

## 未納入本批

- 簡訊／LINE／email 等外部推播（出向資安需另立 ADR）。
- 依人員輪班自動指派案件負責人（目前案件屬於「當班調度員全體」）。
- 常駐排程主動推播（現為查詢時同步）。
