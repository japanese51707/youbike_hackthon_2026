# ADR-014：站點行為指紋、需求密度分層、外部因子降級

## 背景與問題

外部 AI 反饋指出設計盲點：站點容量已「壓縮」了規劃者當年對人口/商圈的先驗估計，而**實際周轉 vs 規劃容量的落差**才是金礦；且六個月歷史周轉是「所有因共同作用後的果」，再補人口這類「因」多半重複。原設計把容量當靜態欄位、學生數等外部因子當主力特徵，未善用歷史行為本身。

需釐清：需求密度這個強指標有「規劃層」與「調度層」兩種用途，混用會出錯（現行無法改柱位，不能拿長期規劃指標當即時調度依據）。

## 決策

1. **新增站點行為指紋模組** `station_profile.py`：從六個月歷史算「站點行為指紋」六指標——
   日夜活動比、平假日比、早晚峰方向、峰型（單/雙/平坦）、需求密度、空滿頻率。
   零外部成本，量的是實際行為（本體），比人口資料（代理）更準。

2. **需求密度分兩層用途，嚴格分開（owner 核准的關鍵界線）**：
   - **規劃層**（長期）：需求密度 = 日均活動量 ÷ 柱位數，記為**站點欄位**；產出「建議增/減柱位清單」當**離線分析與簡報加分項**。
   - **調度層**（即時）：**需求密度不進即時調度觸發**。當下要不要叫調度員調車，仍由規則引擎吃預測區間下界/上界（ADR-004 不變）。現行不能改柱位，長期規劃指標不可當即時觸發依據。

3. **站型分群做兩套、互相對照**：
   - 行為指紋分群（實際使用）：由六指標分群得 4~6 種站型
   - POI 推導區域類型（地理環境，ADR-012 已做）：保留
   - 兩者對照：「應該是什麼型（地理）vs 實際是什麼型（行為）」的落差本身是洞察

4. **外部因子降級（非刪除）**：學生數（school_calendar）等「因」的外部資料，從主力特徵降為
   「**新站冷啟動 fallback + 簡報敘事**」。新站無歷史可算行為指紋，此時靠人口/POI/學生數推初始 profile（呼應 ADR-001 冷啟動）；簡報時「日間就業人口是夜間 2.3 倍」比「模型說的」有說服力。行為指紋當主力。

## 理由與判準

- **行為資料是本體、人口是代理**：六個月周轉已含所有因的作用，行為指紋更準且零成本
- **需求密度的行動價值**：「這 N 站需求密度長期超標，建議增設柱位」是交通局可編預算的具體建議，比預測模型本身更易讓評審點頭
- **規劃層/調度層分開**：避免「不能改的柱位」污染「可執行的即時調度」，呼應核心約束
- **冷啟動仍需外部因子**：新站無歷史，外部「因」不可取代（ADR-001）——故降級不刪除

## 考慮過的替代方案

### 完全砍掉外部人口/學生數因子
- 未採用：新站冷啟動與簡報敘事仍需要，降級不刪除

### 需求密度直接進即時調度觸發
- 未採用：現行不能改柱位，長期規劃指標當即時依據會誤判；違反 ADR-004 分層

### 只做行為指紋分群、砍 POI 區域類型
- 未採用：兩套對照（地理 vs 行為）的落差是洞察，都留

## 影響與後果

### 正面
- 行為指紋是零成本強特徵，站型分群可用人話對交通局描述
- 需求密度產出可行動的柱位建議（簡報亮點）
- 規劃/調度分層清楚

### 負面與代價
- 行為指紋需足夠歷史（新站無效 → 走冷啟動 fallback）
- 需求密度的「活動量」定義需明確（借+還次數 or 淨變化絕對值）

### 尚未解決
- 站型分群的群數與演算法（KMeans？幾群？）待實作時定
- 需求密度「超標/過剩」的門檻待校準

## 介面與相容性

- 新增 `backend/features/station_profile.py`，輸出行為指紋欄位 + 需求密度
- 需求密度欄位加入站點層級資料（長期指標）；柱位建議為獨立分析輸出，不改調度 API
- school_calendar 保留，文件標註用途降級（不改介面）
- 不改 core/interfaces.py 的 PredictionInterval

## 資安與隱私

- 全部由 S3 既有歷史衍生，無外部請求、無個資

## 回復或取代方式

- 行為指紋模組可獨立停用；需求密度欄位可移除
- 設計變更以新 ADR supersede

## 驗證方式

- 行為指紋單元測試（給定序列 → 正確日夜比/峰型/需求密度）
- 站型分群結果可人話描述（通勤住宅/辦公商業/轉運/觀光…）
- 需求密度排序抽查：高值站確實是已知熱門/常缺車站
- 確認需求密度未被規則引擎即時觸發使用（分層驗證）
