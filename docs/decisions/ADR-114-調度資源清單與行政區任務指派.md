# ADR-114：調度資源清單（人員／車輛）與行政區任務指派

## 背景與問題

模型（ADR-113 即時預測）、規則引擎（ADR-111 三層判斷）、緊急度（ADR-112）已備，
能產出「哪些站要調度、補還是取、緊急度多高」。但**還沒有「派給誰、哪台車、怎麼分」的調度層**。

現況（盤點既有程式）：
- `operators` 表 + `operators_repo` 已有調度員主檔 CRUD（含 seed OP-001~003）。
- `tasks` 表 + `task_manager` 已有任務狀態機（pending→assigned→in_progress→completed）。
- `dispatcher.build_dispatch_list` 有排序 + **全域**資源限制（站數上限），但**沒有車隊主檔、沒有行政區分組指派**。
- config.yaml 只有整體數字「調度車數量:20 / 每車容量:25」，**沒有可增刪改的車輛實體**。

缺口：
1. **無車輛主檔**：車輛只是 config 一個數字，無法逐台管理（車號、載運量、狀態），無法增刪改。
2. **人員/車輛清單寫死**：未來 YouBike 公司要用，應由他們丟人力/車隊清單（API）給系統接。現況無抽換介面。
3. **無行政區任務指派**：`district` 只透傳未被使用；任務未按行政區組裝。

owner 要求以「真正可商用、可對接 YouBike 現有系統」思考，不寫死。

## 決策（proposed，待 owner 核准）

### 一、人員／車輛清單為「可抽換 Provider」（模板 + 工廠，比照 ADR-006 DataSource）

清單來源抽象成介面，上層（dispatcher）只依賴介面，不管清單從哪來：

- `OperatorProvider` / `FleetProvider`（介面模板）：定義 `list_* / get_* / create / update / delete` 等契約。
- **內建實作**（開發/demo）：讀本地 DB（SQLite），含 seed 假設值。
- **未來實作**（正式）：接 YouBike 公司的人力/車隊 API，收到即呈現「當前人力車力狀況」。
  抽換只換實作 + 改 config，不動 dispatcher（呼應 ADR-006 換源只改 config）。

工廠 `get_operator_provider()` / `get_fleet_provider()` 依 config 回對應實作（單例，比照 get_data_source）。

### 二、車輛主檔（vehicles 表，新增，可增刪改）

新增 `vehicles` 表，逐台管理：

| 欄位 | 說明 |
|------|------|
| `vehicle_id` | 車號（主鍵，可改顯示名） |
| `max_capacity` | **最高載運量**（台）；預設 15，**依車種可不同、可改**（不寫死在 config） |
| `status` | available / dispatched / maintenance / off_duty |
| `current_district` | **動態**：當前被指派作業的行政區（隨每次任務指派變動，非綁定責任區） |
| `current_task_id` | 當前任務 |
| `is_active` | 1=啟用 0=停用（停用取代刪除，保留稽核關聯，比照 operators） |
| `created_at / updated_at` | 稽核時間戳 |

★載運量是**車輛主檔欄位**（每台可不同），非全域 config；config 的「每車容量」降為「未指定時的 fallback 預設」。

### 三、人員主檔沿用 operators，加動態 current_district

- `operators` 表**加 `current_district`** 欄位（動態，當前作業區；隨任務指派變動）。
- 語意與既有 `current_lat/current_lng/current_task_id` 一致（都是「當前狀態」）。
- **不綁固定責任區**——調度員不預先分區。

### 四、行政區作為「任務組裝約束」（不綁人車，而是綁任務）

- **核心約束：一趟任務（一張派工單）的站點不可跨行政區**（對齊官方「分區恢復平衡」）。
- `tasks` 表**加 `district`** 欄位（這趟任務的行政區）。
- dispatcher 組裝流程：需調度站清單 → **先按 district 分組** → 每組（同區）內按緊急度排序 →
  依車輛載運量切成「單趟不跨區、不超載」的派工單 → 指派車/人 → **回寫 district 到車/人的 current_district**。
- 調度員/車輛不預先分區；被指派後才帶出「這趟在哪區」。

### 五、假設 seed（可增刪改，未來由 API 覆蓋）

- **車輛 41 台**（官方 2025 公布數，比我們估的尖峰 45 保守可靠）：平清單、`max_capacity=15`、
  `status=available`、**不預先分區**（current_district 為空，分區由任務指派動態決定）。
- **調度員 350 名**：編號 seed（如 `OP-板橋班` 或流水號），**不需真名**，可增刪改。
- seed 只是開發/demo 起始值；未來 YouBike 丟 API 進來即以真實清單覆蓋。

### 不改
- 規則引擎（ADR-111）、緊急度（ADR-112）、預測（ADR-113）、AI 只估計規則決策（ADR-004）。
- task_manager 狀態機主體（僅任務資料多帶 district）。
- 既有 operators/tasks repo 契約（僅擴欄，向後相容）。

## 理由與判準

- **可商用對接**：Provider 介面讓 YouBike 現有人力/車隊系統能直接接上，不改核心邏輯（最大痛點）。
- **貼近官方營運**：行政區作為任務約束，對準官方「尖峰後 2 小時內分區恢復平衡」（見 dispatch_scale_validation）。
- **不寫死載運量**：車種不同載運量不同，主檔欄位可改，符合真實車隊多樣性。
- **動態非綁定**：人車不預先分區，貼近「哪裡缺就派哪去」的實際調度，且 current_district 供前端呈現當前分佈。
- **可逆/漸進**：Provider 可切回內建 seed；擴欄向後相容；行政區約束可用 config 開關。

## 考慮過的替代方案

### 車輛用全域 config 數字（維持現況「調度車數量:20」）
- 缺點：無法逐台管理、無法接 YouBike 車隊清單、載運量無法逐台設定。未採用。

### 調度員/車輛綁固定責任行政區
- 缺點：與真實調度「哪裡缺派哪去」不符；owner 明確要求不綁死，改為任務層約束。未採用。

### 人員/車輛清單寫死在程式/DB，不做抽換介面
- 缺點：未來接 YouBike API 要改核心程式。未採用：Provider 介面抽換成本最低。

## 影響與後果

### 正面
- 有完整可增刪改的人力/車隊主檔；能接外部 API；任務按行政區組裝，貼近官方營運。
- 前端可呈現「當前人力車力分佈」（current_district / status）。

### 負面與代價
- schema 新增 vehicles 表、operators/tasks 各加一欄；需寫 vehicles_repo + Provider 介面。
- dispatcher 需加行政區分組 + 載運量切趟邏輯。

### 已於核准時拍板
- **分兩階段**（owner 核准）：本 ADR 只定「資源模型 + 行政區約束框架」；同區內多站的分趟演算法
  （怎麼切趟、路徑順序）由後續 ADR 補（owner 表示後面再補調度做法）。
- **載運量口徑統一為 15**（owner 核准）：config「每車容量」由 25 改為 **15**，作為車輛主檔未指定
  `max_capacity` 時的 fallback；主檔有值則以主檔為準。兩處口徑一致（皆 15）。
- **調度員 seed 用純流水號**（owner 核准）：OP-001 ~ OP-350，不用真名（無真實人名資料）。

### 尚未解決
- YouBike 實際 API 欄位格式未知（Provider 介面先定契約，接取時對映）。

## 介面與相容性

- 新增 `FleetProvider` / `OperatorProvider` 介面 + 工廠（比照 DataSource）。
- 新增 `vehicles` 表 + `vehicles_repo`（CRUD，比照 operators_repo）。
- `operators` / `tasks` 擴欄（current_district / district），向後相容（既有列該欄為 NULL）。
- dispatcher 增行政區分組指派；不改對 Predictor/UrgencyCalculator 的依賴。

## 資安與隱私

- 調度員清單可能含姓名（PII）：seed 用編號不用真名；未來接 API 的真名資料比照 operators 現有處理
  （不外洩、password_hash 已 bcrypt）。
- 車輛主檔無敏感資料。

## 回復或取代方式

- Provider 可切回內建 seed 實作；vehicles 表可停用（is_active=0）不刪；擴欄可忽略（NULL 相容）。
- 設計變更以新 ADR supersede。

## 驗證方式

- vehicles_repo CRUD 測試（增刪改查、停用保留）。
- Provider 抽換測試：內建實作 ↔ mock/外部實作可切換，dispatcher 不改。
- 行政區約束測試：組出的每張派工單站點同屬一區、不超載（≤ 車輛 max_capacity）。
- 指派後 current_district 正確回寫車/人。
- 跑既有 dispatcher/task_manager/operators 測試不破壞。
