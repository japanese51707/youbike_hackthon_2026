# ADR-101：預測特徵因子模組化與外部資料源

## 背景與問題

ADR-001／002 已定「單一 LightGBM 模型 + 分層參數」，但**模型要吃哪些特徵、各特徵的資料從哪來**尚未定案（治理規範第二節：「特徵責任」屬必須 ADR 的類別）。

預測目標：以當前站點狀態預測「下一時段」的淨流入/流出量（進而得可借車數與區間）。時段長度依即時資料更新頻率而定——**官方目前提供 30 分鐘一筆，故先以 30 分鐘為預測窗口**；未來若換更高頻即時源（如 5 分鐘），窗口需可調。

需要先決定：初期納入哪些外部影響因子、每個因子的資料源與粒度、以及如何組織成可獨立維護的模組。不決定的後果：特徵散落、資料源臨時硬接、無法分工、交叉影響無從談起。

## 決策

1. **每個影響因子做成獨立模組**（一因子一檔），放 `backend/features/`，各自負責「載入原始資料 → 對齊到 (站點/縣市, 時間) → 輸出特徵欄位」。初期只做**單因子**，不在此階段處理交叉影響（交叉留待後續 ADR）。
2. **初期納入四個因子 + 資料源**：
   - **假日因子** `calendar_holiday.py`：政府行政機關辦公日曆表（新北市開放平台 dataset 308DCD75，逐日：是否放假/節日類型）
   - **學期/學生數因子** `school_calendar.py`：寒暑假日期區間（分國小/國中/高中/大學）+ 教育部各級學校縣市別學生數（靜態），輸出「新北市當期各級在學影響人口」推估
   - **天氣因子** `weather.py`：CODiS 重建歷史逐時觀測（Raingel/historical_weather，新北測站；溫度/濕度/雨量/風速），對齊到最近測站
   - **地形因子** `terrain.py`：站點座標 + 高程推坡度，套 config.terrain_thresholds 分類（flat/gentle/moderate/steep）
3. **預測輸出**：下一時段（預設 30 分鐘，可調）的淨流入/流出量估計 + quantile 區間（下界/上界），對接既有 `core/interfaces.py` 的 `PredictionInterval`（不改介面）。
4. **天氣資料分兩階段（owner 核准）**：訓練與研究階段**只用歷史資料**（CODiS 重建庫）；即時 CWA API 待模型建好、要「以現況預測下個時段」時才導入。
5. **不做**：不在特徵層做決策（ADR-004）；訓練階段不引入即時天氣 API 金鑰（用公開歷史庫）；不做每站一模型（ADR-001）；此階段不做交叉影響（單因子先行）。

## 理由與判準

- **可維護／可分工**：一因子一檔，單獨測試、單獨換資料源，符合 steering 模組化與 ADR-006 可抽換精神
- **資料可得性**：四個因子的資料源都已實際查證可公開取得（見追溯），不依賴付費或需金鑰的服務
- **交付時間**：先單因子、後交叉，讓管線能先跑通（呼應「先設計完整因子、再驗證」的方向）
- **對齊既有決策**：輸出對接 PredictionInterval，不改跨人契約（ADR-005）

## 考慮過的替代方案

### 方案 A：特徵全寫在一個 features.py

- 優點：檔案少、初期快
- 缺點：因子混在一起、難單獨測試/換源、難分工
- 未採用原因：違反模組化，因子一多就失控

### 方案 B：即時天氣用 CWA opendata API（需金鑰）

- 優點：官方即時
- 缺點：歷史觀測取得麻煩、需金鑰管理（金鑰外洩風險，見 steering §11.1）
- 未採用原因：訓練用歷史資料，公開重建庫已足夠；即時源留到現場再接

### 方案 C（採用）：四因子獨立模組 + 公開資料源

- 優點：可維護、可分工、資料可得、對齊既有 ADR
- 缺點：資料對齊（測站→站點、縣市→站點）需額外處理
- 採用。

## 影響與後果

### 正面
- 特徵責任清楚，B 可分工開發各因子
- 每個因子可獨立驗證其對預測的貢獻（feature importance）

### 負面與代價
- 資料對齊工作量（天氣測站對站點、學生數縣市對站點）
- 外部資料來源若停更或格式變動需維護（用公開 repo 有此風險）

### 尚未解決
- 交叉影響（如「雨天×尖峰×假日」）留待後續 ADR
- 學生數→實際騎乘影響的轉換係數需校準（初期用粗估）
- 預測窗口未來改 5 分鐘時的重訓需求

### 假日因子消融結論（2026-09-03 補記，全量 1583 站 × 6 月，L2 探針）

假日因子測了**兩種用法**，結論不同（關鍵：不是「假日有沒有用」，而是「怎麼用」）：

**用法一：加料（額外新增 is_holiday/is_national_holiday/is_long_weekend 三特徵）→ 不採用。**
- 全量幾乎全切面負向（已空區 120 分 -2.55%）。原因：`is_holiday` 與基準既有的 `is_weekend`
  高度重疊（放假日多數就是週末），無新資訊；多加的稀疏特徵反讓已空區過擬合雜訊。

**用法二：is_weekend 升級為 is_dayoff（週末 OR 國定假日視為放假、補班日視為上班）→ 採用（預設開啟）。**
- 全量：Δ≠0 **全視野一致正向**（+0.20~0.42%）；全樣本微幅正（±0.2%）；已空區有正有負、不穩定。
- 改善幅度小，但 **owner 定案採用**，理由是**概念正確性優先於這半年的微小數字**：
  「平日的國定假日就是放假」邏輯上正確；這半年國定假日僅春節/清明幾天訊號本就弱，
  未來全年資料（含雙十/中秋等平日型國定假日）它會更有價值——**為全年鋪路**。
- 落地：`build_training_frame(dayoff_mode=True)` 為預設；`is_weekend` 欄的值改為 is_dayoff 定義，
  連 `station_slot_p50` 分組也按放假型態。特徵欄名不變（乾淨對照），消融可用 `dayoff_mode=False` 關閉。
- ★週末本身的影響一直都在基準（`is_weekend`/`weekday`），此定案只是把「國定假日」也正確歸入放假。

**保留**：calendar_holiday.py 模組不刪（用法二依賴它；用法一的加料特徵留著備查，全年資料後可重評）。

### 地形因子消融結論（2026-09-03 補記，全量 1583 站 × 6 月，L2 探針）

**高程資料源修正**：原設計用 Open-Elevation（SRTM，不穩且台灣城市尺度誤差大），
改用 **OpenTopoData mapzen DEM**（Copernicus 合成，較準、可批次、免金鑰）。
1578 站高程存 `_elevation_cache.json`。
**取樣距離校準**：初版用 ±50m 取樣算坡度，但 mapzen DEM 約 90m 網格，50m < 網格 →
放大插值雜訊（實測中位坡度虛高到 8%、396 站被誤判為陡坡）。**改 ±200m 取樣**（匹配網格）後
中位坡度修正為合理的 4%，分布：平坦 285/緩 805/中 327/陡 161（陡坡多在山區站，符合實際）。

**消融結果（全量）**：

| 視野 | 全樣本 | 已空區 | Δ≠0 |
|------|--------|--------|------|
| 30分 | +0.01% | -0.25% | -0.01% |
| 60分 | +0.12% | +0.73% | +0.15% |
| 90分 | +0.33% | +1.75% | +0.21% |
| 120分 | +0.56% | **+2.27%** | +0.37% |

**留（低邊際，比照天氣）**：全樣本/Δ≠0 幾乎無效果，但**已空區長視野 +1.75~2.27%** 有穩定正向。
低邊際原因：多數站在平緩地帶訊號弱，且「上坡站借車意願低」已被行為指紋（歷史周轉/空滿頻率）吸收
——地形是「因」、行為是「果」，果已被學走（呼應 ADR-104「行為是本體」）。
但地形對**新站冷啟動有獨特價值**（新站無行為歷史，但有座標可查坡度），與 POI 同為「靜態站點屬性」。
落地：`build_training_frame(with_terrain=True)`，海拔+坡度%+坡度分級碼。非主力（主力=行為指紋+POI）。
高程資料另可用於坡度地圖標示與簡報敘事（陡坡站的電輔車調度建議）。

## 介面與相容性

- 新增 `backend/features/` 模組，各因子輸出特徵欄位供模型訓練/推論
- **不改** `core/interfaces.py` 的 `PredictionInterval`（下界/上界/horizon）——研究產物最終對接此介面
- config 可能新增各因子的資料路徑/參數（沿用參數外部化原則）

## 資安與隱私

- 外部資料皆為公開政府/學術開放資料，無個資
- 不引入需金鑰的即時 API（避免金鑰管理風險）
- 天氣資料來自第三方 repo，視為不可信輸入：載入時驗證格式、缺值明確標記（NFR-5）

## 回復或取代方式

- 各因子模組可獨立移除/停用（模型退回不含該特徵）
- 若因子設計改變，以新 ADR supersede，不改寫本 ADR

## 驗證方式

- 各因子模組有單元測試（給定日期/座標 → 正確特徵值）
- 模型層驗證：時間切分（1~5月訓、6月驗，ADR-002），比較「含因子 vs 不含」的 MAE 與區間覆蓋率
- feature importance 檢視各因子貢獻
