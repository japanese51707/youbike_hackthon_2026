# ADR-126：未受供給限制的需求估計

## 背景與問題

系統的目標變數是「存量淨變化 Δ」。ADR-105 早已寫明：站點空了（可借=0）或滿了（可還=0）時，
觀測到的 Δ=0 是被物理邊界壓抑的值，不是真實需求——想借的人看到沒車就走了，這個需求不會出現在資料裡。
ADR-105 把「還原被壓抑的真實需求」列為選配加分項，一直沒做。

第三批全量評估讓這件事的代價變得具體：6 月驗證集裡有 3～4%（每視野 6.7～8.9 萬列）是截斷列，
在這些列上用觀測 Δ 比 MAE 會讓「永遠猜 0」的基準天生占便宜，因此**整體指標會系統性低估模型**，
而且更重要的是——**後台看到的「缺 N 台」在空站上一定是低估的**，因為 N 是從被壓抑的觀測推出來的。

## 決策

沿用 ADR-105、111、115、121、122；不取代任何 ADR。

1. **只做輸出，不進決策**：估計值以**獨立欄位** `unconstrained_demand` 輸出，附 `demand_basis` 說明依據。
   觸發判斷、目標水位、緊急度、派工量一律**維持使用既有的淨變化預測**，不因本估計改變。
   這維持 ADR-122 §4 的界線：模型輸出是淨變化，不是需求量，兩者不得混用。
2. **估計方法（站內自比，不跨站外推）**：以該站訓練期**未觸底時**同一（放假型態 × 時段）的流出／流入量
   中位數，當作該時段的「未受限需求」基準。站點空著時，`unconstrained_demand` ＝ 該基準；
   站況正常時不輸出估計（值為 null），因為此時觀測本身就沒有被壓抑。
3. **不跨站推估**：ADR-105 曾提到「用同群站同時段未觸底的流量反推」。本 ADR **不採用**跨站方案——
   跨站需要群集定義與規模縮放兩層假設，任一層錯都會放大誤差，且無法驗證。站內自比只需要
   「這個站在沒空的時候大概流出多少」這一個可直接量測的量。
4. **凍結統計進模型包**：`station_slot_uncensored_p50` 由訓練期算出並寫入 serving 特徵包，
   線上只查表不重算（沿用 ADR-121）。此統計**不進特徵欄位**，不影響模型輸入與既有雜湊比對。
5. **預設關閉**：`config.prediction.輸出未受限需求估計`，預設 `false`。關閉時欄位不出現，行為與現在相同。
6. **明確標示不確定性**：`demand_basis` 只會是 `station_slot_uncensored`（有足夠樣本）或
   `insufficient_samples`（樣本不足，值為 null）。不得在樣本不足時給一個看起來很確定的數字。

## 理由與判準

- **誠實優先於好看**：空站的真實缺口一定大於觀測推得的缺口；不揭露等於讓後台系統性低估。
- **決策邊界不動**：需求估計的不確定性遠高於淨變化預測，不應該讓它影響派幾台車。
- **可驗證的方法勝過理論上更好的方法**：站內自比可以用同站未觸底的歷史直接檢核；跨站外推不行。
- **與評估協定呼應**：第三批已把截斷列拆開報，本 ADR 補上「那些列的真實需求大概是多少」的估計。

## 考慮過的替代方案

### 方案 A：把插補後的需求當訓練目標

- 優點：模型直接學真實需求，截斷列不必排除。
- 缺點：用估計值當標籤會把估計誤差寫進模型，且無法分辨模型錯還是插補錯。
- 未採用原因：風險高且不可驗證；ADR-122 才剛把標籤完整性整理乾淨。

### 方案 B：跨站同群插補（ADR-105 原始構想）

- 優點：對從未有過正常流量的站（長期空站）也能給估計。
- 缺點：需要群集與規模縮放兩層假設，且無法用該站自己的資料驗證。
- 未採用原因：見決策第 3 點。

### 方案 C：不做，維持現狀

- 優點：零風險。
- 缺點：後台持續看到被低估的缺口，且無法向外解釋為什麼指標在截斷列上難看。
- 未採用原因：owner 已核准納入本批。

## 影響與後果

### 正面

- 空站的缺口有一個誠實的下限以外的參考值，簡報與後台都能解釋「官方快照低估了什麼」。
- 截斷列的討論從「指標難看」變成「我們知道難看在哪、也能估出被壓抑了多少」。

### 負面與代價

- 多一份凍結統計，模型包變大、換版時要一起產生。
- 估計只在站點觸底時有值，覆蓋率天生有限。
- 樣本不足的站（新站、長期空站）給不出估計。

### 尚未解決

- 沒有 ground truth 可以驗證估計的準確度，只能做合理性檢核（例如與同站未觸底時段的分布比較）。
- 未處理「滿站的還車需求」與「空站的借車需求」在行為上的不對稱。
- 現行 `_models/` 的特徵包沒有這份統計，要到下次重訓才有；在那之前即使開啟旗標也會回 null。

## 介面與相容性

`backend/prediction/feature_pipeline.py` 新增訓練期統計 `station_slot_uncensored_p50`（不進 `feature_cols`），
`serving_features` 的 bundle 新增同名可選區塊；缺這個區塊時視為沒有估計能力，回 null 且不拋錯，
既有模型包不需重新產生即可運作。規則引擎輸出新增 `unconstrained_demand` 與 `demand_basis`
（旗標關閉時不出現）。既有欄位名稱、型別與語意皆不變。

## 資安與隱私

無。純離線統計與本機檔案讀取，不新增外部請求、憑證或個資。

## 回復或取代方式

把 `輸出未受限需求估計` 設回 `false` 即不輸出；bundle 內的統計留著不影響任何行為。
要讓估計進入決策，必須另立新 ADR 並重新檢視 ADR-122 §4 的輸出語意界線。

## 驗證方式

- pytest：站點觸底時才有估計、站況正常時為 null；樣本不足時 `demand_basis=insufficient_samples` 且值為 null；
  開關關閉時輸出欄位不存在且其餘欄位逐欄不變；**估計值改變不影響 action／quantity／target_available／緊急度**
  （決策邊界測試）；bundle 缺該區塊時不拋錯。
- 合理性檢核：以固定資料驗證估計等於該站未觸底時同時段的中位數。
- `git diff --check`。
