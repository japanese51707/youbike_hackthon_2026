# ADR-331：自動配單非同步化與執行視窗（流動圖）

## 背景與問題

自動配單一輪要掃全市站、逐一組單與確認，雲端常超過前端 20 秒逾時 → 按「立即配單」回
「服務回應逾時」。且背景輪靜默運作，操作者看不出有沒有在動、下一輪何時跑、配了什麼。

## 決策

1. **run-now 改非同步**：`POST /dispatch/auto-dispatch/run-now` 立刻回 `{started, progress}`
   （背景 thread 跑一輪），不等跑完 → 不逾時。
2. **進度狀態機 + 端點**：`scan_once` 逐筆更新 `_progress`（phase: selecting→dispatching→done、
   run_id、queue_total、processed、placed[]、resources、stopped_because）；
   `GET /dispatch/auto-dispatch/progress` 供前端輪詢。
3. **執行視窗**（`AutoDispatchRunModal`）：Steps 流動圖（選取清單→逐筆配置→完成）+ 即時資源
   遞減（可用車/總部車/可派人/總部人）+ 逐筆流動清單。手動按「立即配單」跳出；前端每 4 秒
   偵測 run_id 變化，背景輪開新一輪也自動跳出；phase=done 後自動關閉並刷新儀表板。
4. **例外收尾**：scan_once 任何例外都把 progress 收尾成 done（附原因），避免永遠停在 selecting。

## 理由與判準

- 非同步解逾時；進度狀態機讓背景與手動共用同一份可觀測進度；例外收尾避免視窗卡住。
- run_id 遞增讓前端辨識新一輪，背景輪也能自動跳窗，符合 owner「背景輪也要跳出」的要求。

## 影響與後果

- 正面：不逾時、過程可視化、背景與手動一致。
- 代價：新增 progress 全域狀態與輪詢端點；手動觸發改為背景 thread（run_now 不再同步回結果，
  改回 started/progress，測試相應調整）。

## 介面與相容性

- `run_now()` 回 `{started, progress}`（原為 `{placed_count, placed}`）；`run_status()` 增 progress。
- 新增 `GET /dispatch/auto-dispatch/progress`。前端 `AutoDispatchRunModal` + DashboardPage 輪詢。

## 驗證方式

- `tests/test_auto_dispatch.py`：run_now 非同步啟動、progress 端點、跑完 last_run 更新，皆通過。
- 雲端實測：立即配單不再逾時，視窗顯示流動圖與逐筆結果。
