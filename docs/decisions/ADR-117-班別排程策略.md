# ADR-117：班別排程策略（尖峰折返 / 離峰效率最大化 / 大夜跨區）

## 背景與問題

ADR-116 定義了三班角色。但「每班在不同時段怎麼排任務」策略完全不同，需明確定義排程演算法，
否則 dispatcher 無法據以產出派工單。歷史分析（dispatch_ops_analysis.md）顯示：

- 尖峰工作量遠大於離峰（早尖峰 1738 台 vs 尖峰後 103 台），且尖峰是「熱門站對之間高頻來回」。
- 離峰是「零星站點、一趟帶多站、跑完換下一趟」。
- 大夜是「跨區大宗復原、長距離」。

三種模式的排程邏輯不能用同一套。owner 已定調各班策略，本 ADR 落地為可實作的排程規則。

## 決策（proposed，待 owner 核准）

排程依「當前時段」切成三種模式。時段邊界由 ADR-116 的 config `shifts` + 尖峰時間決定。

### 一、尖峰模式（折返跑 shuttle）— 早 07:30–09:30 / 晚 17:00–19:00

- **折返組（cluster，非死綁一對站）**：同行政區內選定「一組站」（≥2 站，可含 1 收多放或多收多放，
  例：1 個滿站收車 + 2 個順路空站放車），**選定後這台車就固定在這組站之間來回循環**
  （收滿→依序放→回收→…），直到尖峰結束。
- **組的選法**：以「怎麼跑最能有效率解決卡站」為目標——用歷史尖峰流向（狂流出↔狂流入站）+
  地理鄰近（同區、順路）組成一組，使一台車在這組站間的循環能持續消化人流。
- **車數**：依歷史估算（早 ≈39 / 晚 ≈38 台，各區分配見分析文件）。系統在尖峰前把車佈到各折返組。
- **特性**：尖峰模式**不追求一趟帶多站長跑**，追求「選定一組站高頻循環」（最快消化尖峰人流）。

### 二、離峰模式（效率最大化）— 尖峰前預佈 + 尖峰後至收班

- **目標：效率最大化 = 每台車每趟的搬運效益最高**（不是單純少跑近跑；owner 確認）。
  具體：一趟盡量裝滿（趨近車容量）+ 路徑短 + 站點依緊急度優先，使「每公里搬運量」最大化。
- **組裝**：沿用 ADR-114 `assign_by_district`（按區分組、載運量切趟、一趟不跨區）+ ADR-115 動態目標水位定每站量，
  再加「趟內路徑順序（先取後放、就近串接）」。
- **尖峰前預佈的關鍵約束（時間不撞尖峰）**：尖峰前派的任務，估「通勤時間 + 作業時間」，
  若預計完成時間會超過尖峰起點 → **不派這趟**（避免車卡在半路錯過尖峰佈署）。
- **跑完接下一趟＝輔助決策，非自動派工（人在迴圈，steering §6）**：車完成一趟後系統回報
  「此車任務結束 + 當前位置」給後台管理人員；系統**依該車當前位置，計算各站緊急度 + 距離，
  算出「最低成本最有效率」的下一趟建議**（排序呈現），**由後台管理人員拍板**下一趟去哪，系統不自動派。
  這是系統的核心定位：決策輔助工具（算好建議 + 排序），不是自動最佳化派工器。

### 三、大夜模式（跨區大宗復原）— 22:00–翌日 06:30

- **可跨區**（ADR-116，config `allow_cross_district=true`）。
- **目標：最低成本 + 最大載運量** = 趁人流少，用最少趟次把白天積累的跨區失衡一次搬回。
  裝滿再跑、長距離可接受（夜間路況好、時間充裕）。
- **組裝**：解除 assign_by_district 的不跨區約束，全市範圍配對「大宗缺車區 ↔ 大宗滿車區」，
  以「總搬運量 / 總趟次」最大化（單位趟成本最低）排程。

### 四、共同約束（所有模式）

- **工時**（ADR-116）：排程時排除已達連續工時上限者；一趟預估時間納入工時累計。
- **車容量**（ADR-114）：一趟總搬運量 ≤ 車輛 max_capacity。
- **緊急度優先**（ADR-112）：同模式內，緊急度高的站/對先服務。
- **KPI 估算**：每趟估交通時間（距離÷config車速）+ 作業時間（站數×每站分鐘）+ 載運量，
  供後台管理人員看進度、算執勤 KPI、安排下一步（controller 決策台）。

### 五、後台手動介入與任務認領（人在迴圈的操作層，steering §6）

系統給建議、後台管理人員（controller）拍板；後台並保有手動介入權，且認領狀態全程可見（防重複接/漏做）。

**指令呈現用「目標存量」而非「增減量」**：
- 給現場人員的主指令是「**○○站補到 X 台 / 抽到剩 X 台**」（目標存量，來自 ADR-115），
  非「補 8 台 / 抽 5 台」。理由：人到現場時站況可能已變，目標值自帶校正；且回報時能直接比對
  「目標 vs 實際」看出落差。增減量（現況→目標的預估）為輔助資訊（讓人知道約帶幾台車）。

**任務層（整張派工單）**：
- in_progress 任務**不可被後台轉派**（尊重現場，人已在路上）。
- 執行者本人可「**取消/退回**」任務（**須說明原因**）→ 任務脫離 in_progress → 後台再重排給他人。

**站點層（任務內個別站）**：
- 後台**可對任務內個別站臨時抽離/增加**（緊急用）——這類操作通常很緊急，故授權後台。
- 抽離/增加時**必須通知現場調度人員**（人為介入 + 現場同步，走 ADR-118 通知機制）。
- **抽離時偵測該站當下狀況**：若調度需求已消失（不缺不滿）→ 視為已完成、不回池；
  若需求仍在 → 清除認領標註、回待調度池、重新排進建議。

**認領標註（防重複/防遺漏）**：
- 站被納入某任務 → 標註「已被 X 認領」（後台地圖一眼看出哪些站已被處理、哪些待接）。
- 站被抽離（且需求仍在）或退回 → 清除標註 → 回可接手池，他人可接。

**逐站完成回報（閉環驗證，steering §4/§6）**：
- 現場人員**每完成一站就回報「該站實際存量」**（actual_available）。一張任務跑 N 站，N 站各自回報。
- 回報作用：即時更新站況（防重複派）、算實際 KPI、供「目標 vs 實際」落差記錄。
- **任務完成 = 所有站皆完成回報，或被抽離且需求已消化**。
- 「建議目標 vs 實際回報」的落差**先只記錄**（供日後校準模型/緊急度），本階段不做自動校準回饋
  （避免引入回饋迴路的大工程）。

**稽核留痕**：所有人為介入（插入/抽離/增加站、取消/退回、轉派）與逐站回報，記 audit_logs（誰/何時/原因）。

### 排程輸出
每趟派工單（trip）擴充 ADR-114 的結構，加：`shift`（班別）、`mode`（peak_shuttle/offpeak/night）、
`est_travel_min`、`est_work_min`、`est_total_min`、`shuttle_cluster`（尖峰折返組的站清單，非尖峰為 None）。
- 每站子項目帶：`target_available`（目標存量，主指令）、`est_quantity`（預估增減量，輔助）、
  `claim_status`（認領狀態）、`actual_available`（完成回報實際存量）、站級狀態（pending/completed/removed）。
- 離峰模式另有「下一趟建議」輸出（依車輛當前位置算的候選站排序：緊急度高、距離近、單位成本低者優先），
  供後台管理人員拍板，非自動派工。

### 不改
- ADR-114 資源模型與 assign_by_district 主體（離峰模式沿用，大夜解除跨區約束，尖峰另走折返分支）。
- ADR-115 動態目標水位（離峰/尖峰的每站量仍由它算）、ADR-116 角色班別。

## 理由與判準

- **對準真實營運**：三模式對應歷史觀察到的三種調度型態，vs 單一排程更貼合實務、更好解釋。
- **效率最大化的正確定義**：釐清為「單位成本搬運效益最大」，避免「少跑」與「多載」兩目標打架。
- **時間不撞尖峰**：尖峰前預佈加完成時間檢查，是真實調度的關鍵約束（車不能卡在半路）。
- **善用既有基礎**：離峰直接用 ADR-114/115，只加路徑順序；尖峰/大夜為新分支但共用資源模型。
- **可解釋**：確定性規則排程（非黑箱最佳化），符合 steering §5（規則決策）與題目「機關可理解介入」。

## 考慮過的替代方案

### 全時段用單一排程（assign_by_district）
- 缺點：無法表達尖峰折返（高頻來回）與大夜跨區，離峰以外時段失真。未採用。

### 尖峰也用「一趟多站」而非折返
- 缺點：尖峰站況變化極快，多站長趟回來時前面的站又失衡；折返「單對高頻」才追得上人流。未採用。

### 大夜也綁區
- 缺點：與真實「大宗跨區復原」不符，夜間分區反而低效。未採用（ADR-116 已定大夜可跨區）。

### 用 VRP（車輛路徑問題）最佳化求解器算全域最優
- VRP = 給定 N 車 M 點 + 容量限制，求「每車跑哪些點、什麼順序」總成本最小的數學規劃（如 OR-Tools）。
- 缺點：(1) 可解釋性差——算出的解難向機關解釋「為何這樣派」；(2) 計算重、站多時即時性差；
  (3) 難手動調整（改一站要全域重算），與「人在迴圈」衝突。
- **未採用**（owner 確認）。改用**啟發式規則排程**（heuristic）：以「最急先服務、就近串接、裝滿出發、
  依車位置算下一趟建議」等合理規則逐步組裝——不保證數學最優，但夠好、快、可解釋、好調整，
  且符合系統「決策輔助（算建議由人拍板）」的定位（steering §5/§6）。

## 影響與後果

### 正面
- 三班差異化排程對準真實營運；效率最大化定義清晰；尖峰佈署不撞時間。
- 為後台管理人員提供每趟 KPI 估算與進度追蹤。

### 負面與代價
- dispatcher 需加尖峰折返分支 + 大夜跨區分支 + 離峰路徑順序 + 時間估算；trip 結構擴充。
- 尖峰折返對配對需歷史流向表（離線算，比照 dispatch_ops_analysis）。

### 尚未解決
- 折返組的具體組成演算法（一組幾站、1收多放怎麼選）——實作時細化，先定「同區狂流出↔狂流入、地理近、
  循環最能消化卡站」原則。
- 路徑順序演算法（先取後放 + 最近鄰）為啟發式，非最優；夠用即可。
- 尖峰折返組表的更新頻率（每日離線重算 vs 每週）——歸每日批次層（比照特徵三層）。
- 「下一趟建議」的緊急度×距離綜合評分公式（離峰滾動）——實作時定，先定「緊急度高、距離近、
  單位成本低者優先」原則。

## 介面與相容性

- trip 結構加 shift/mode/est_*/shuttle_pair 欄位（向後相容，離峰 trip 的 shuttle_pair=None）。
- dispatcher 對外 assign_by_district 保留（離峰用）；新增尖峰折返、大夜跨區的排程入口。
- 依賴 ADR-116 的班別判斷（給定時間 → 班別 → 模式）。

## 資安與隱私

- 無（純排程邏輯，無對外通訊、無 PII）。

## 回復或取代方式

- 移除尖峰/大夜分支、全時段退回 assign_by_district 即回復；改方向以新 ADR supersede。

## 驗證方式

- 尖峰模式：折返對同區、車數落在歷史估算量級；折返對取滿站放空站。
- 離峰模式：一趟不跨區不超載（沿用 ADR-114 測試）、路徑先取後放、預佈完成時間不超尖峰起點則不派。
- 大夜模式：可跨區、單位趟搬運量最大化。
- 共同：工時上限排除、車容量上限、緊急度優先、KPI 估算欄位正確。
- 後台介入：in_progress 不可被轉派（raise）；執行者取消/退回須帶原因並脫離 in_progress；
  站點抽離時需求消失=完成、需求在=清標註回池；認領標註正確設/清；逐站回報 actual_available
  並記落差；人為介入寫 audit_logs。
- 指令呈現：站指令為目標存量（target_available）非增減量。
- 跑既有 dispatcher/task_manager 測試不破壞。
