# ADR-333：自動配單在真實站況下的配單修正與殘缺趟清理

## 背景與問題

自動配單在 mock 測試全過，但接上真實 S3 站況後幾乎「配出 0 張」。追 diagnostics（193 站）發現
三個機制連環擋單，且產生了「只有取車無補車」的殘缺趟落地成髒任務：

1. **觀測比對（136 次「站點觀測已更新」）**：confirm 比對「組單當下 vs 即時」站況，只要
   `observed_at` 不同就擋。自動配單組單走 60s 快取清單、即時站況來自 S3 中繼，兩者 observed_at
   幾乎必不同 → 幾乎每張自動單被擋。
2. **target 浮點（163 次「實際存量必須為非負整數」）**：規則引擎產浮點目標水位（如 21.8），
   validate_stations 用要求嚴格整數的 inventory 檢查 target_available → 拋錯。
3. **onboard 過期（25 次 vehicle_onboard_stale）**：閒置車舊載量觀測過期，feasibility 擋。

## 決策

1. **自動配單跳過觀測比對**：`confirm(skip_observation_recheck=True)`——自動配單是機器用當下清單
   即時組單+立刻確認，不需「防人用過期預覽」那層保護（那對人工組單才有意義，人工路徑不變）。
   資源驗證／載量守恆／認領檢查（validate_resources 等）仍全保留，是防重複配的真防線。
2. **target 整數化**：`validate_stations` 驗 target 前 `round(float(...))`；`_fill_station_targets`
   對已存在的 target 也整數化。台數語意本為整數。
3. **onboard 過期比照未知**：`_preset_onboard` 在 onboard「過期」（observed_at 缺失或超過有效期）
   時也套系統預設值 + 蓋新觀測時間（過期的舊值等同失效，符合 ADR-318 自動預設精神）。
4. **殘缺趟清理**：`POST /dispatch/cleanup-malformed-tasks`（dispatcher/maintainer）掃描取消
   「route 全取車無補車／含 0 量站」的 assigned/in_progress 任務，走正規 release 釋放車人，
   讓站回緊急清單重配。清理修正生效前配出的舊髒任務。

（另有隊友並行修正：ADR-334 單站需求超容量不讓整輪配 0、ADR-322 部分補車、ADR-321 供車站——
本 ADR 與其疊加，共同讓自動配單在真實站況下正常運作。）

## 理由與判準

- 觀測比對對人工組單重要（防用舊預覽），但對機器即時配單反成阻礙——用參數精準區分兩種來源。
- target/onboard 修正解決真實資料（浮點、過期）與 mock（整數、新鮮）的落差，不改核心語意。
- 殘缺趟清理走既有 cancel/fail+release 鏈路（不硬刪 DB、有稽核），釋放被髒任務占用的資源。

## 影響與後果

- 正面：自動配單從配 0 張恢復正常（實測配出 40+ 張早班任務、組成皆有取有補）；髒任務清空。
- 代價：自動配單不再做觀測比對（可信來源，可接受）；清理端點為管理操作（限 dispatcher）。
- 尚未解決：早尖峰全市缺車、總部車有限時仍有站配不出（真實資源限制，非 bug；可調總部車數）。

## 介面與相容性

- `confirm` 增 `skip_observation_recheck` 參數（預設 False，人工路徑行為不變）。
- `validate_stations`/`_fill_station_targets` target 整數化；`_preset_onboard` 加過期判斷。
- 新增 `POST /dispatch/cleanup-malformed-tasks`。

## 驗證方式

- 本機真實 S3 站況模擬：三大錯誤（觀測/非負整數/stale）歸零，draft 全部有取有補（0 個只有取車）。
- 雲端實測：最新一輪任務組成正常（取車+補車）；清理端點清掉 14 個殘缺任務、再清回 0。
- 後端測試全套通過（僅 flaky 並發測試偶失敗）。
