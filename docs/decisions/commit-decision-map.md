# Commit → Decision 時序追溯

本文件依 Git 歷史由舊到新分類每一筆 commit。目的不是「每個 commit 寫一份 ADR」，而是回答：該 commit 建立、實作或驗證了哪個長期決策；若只是文件同步或局部工具，明確標為不需 ADR。

## 判讀原則

- `決策`：首次鎖定或實作會限制未來方向的選擇，對應 ADR。
- `實作／驗證`：沿用既有 ADR，不另立文件。
- `文件同步`：不改決策，只更新說明或里程碑。
- `局部工具`：不改產品架構、API 或長期介面。
- 追溯 ADR 是依 commit、Spec 與現存程式重建；無證據的當時動機不推測。
