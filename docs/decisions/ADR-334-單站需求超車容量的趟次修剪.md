# ADR-334：單站需求超過車容量時的趟次修剪（不讓整張單卡死）

## 背景與問題

早尖峰大站在動態目標水位（ADR-115）下，單站補車量常常就超過一台車的載運量（15 台）。
`_pack_supply_aware_trip` 是「seed 站無條件先入趟」，之後才逐站檢查容量——當 seed 站本身
需求就超容量時，整趟會被判超載而配 0 張，讓自動配單卡死。

## 決策

新增 `_fit_trip_to_capacity(stations, capacity, onboard)`：用「這台車實際會帶出去的載量」
把趟次修剪成車真的載得動的規模（保留載得動的站、移出超出的站），而不是整張作廢。
總部車的出車載量由 `_preset_onboard_value` 決定（ADR-318，非 0），避免總部趟被誤判為
一台都放不出而整趟清空。單站需求超容量時下修該站搬運量至車能負荷，仍配出可執行的一趟。

## 理由與判準

- 「配得動多少就配多少」勝過「因單站超量而整輪 0 張」，符合部分補車（ADR-322）精神。
- 修剪在裝箱後、以實際出車載量為準，與載量守恆（ADR-123）一致。

## 影響與後果

- 正面：大站/尖峰不再讓自動配單整輪卡死；配出可執行規模的趟次。
- 代價：單趟可能無法一次補滿大站需求（分次補），屬合理取捨。

## 介面與相容性

- 新增 `_fit_trip_to_capacity`；build_from_station 於選定車後套用。標準欄位不變。

## 驗證方式

- `tests/test_capacity_fit.py`：單站需求超容量時仍配出（修剪後）可執行趟次，通過。
