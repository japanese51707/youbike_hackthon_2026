# ADR-205：四頁角色導向資訊架構與無捲動固定視窗版面

> **修訂註記（2026-09-05，owner 核准）**：移除原「司機桌機頁 `/operator`」。理由：桌機司機情境不成立（司機在車上用手機），而其桌機版若改為調派員的車隊監控，會與調度面板職責重疊、且本專案 mock 規模過小不值得獨立成頁。**司機改為僅手機端 `/driver`**；若需車隊/任務執行監看，未來以調度面板的分頁或小面板承載，不另立頁。本註記透明記錄變更、不改寫下方原始決策內容。路由集合更新為：`/dashboard`（預設落地）、`/driver`、`/overview`、`/twin`。

## 背景與問題

前端經 ADR-202／204 完成地圖遷移與戰情室視覺後，功能快速累積（環形站點、Voronoi、Hexagon、調度弧線、示意路線、站點多維屬性、時序面板等），但三個頁面（`/dashboard`、`/operator`、`/overview`）每頁都同時混入「日常操作」「成效報告」「炫技展示」，導致畫面過載、對象不清。

盤點 Spec §2 角色後確認：真正**每日操作**的只有調派員（工作台）與外勤司機（行動端）；長官是**間歇/簡報式**觀眾；此外黑客松還有**評審**這個隱形展示對象。原本「三頁各服務所有人」是雜亂根因。

不做決策的後果：功能繼續往三頁堆疊，操作者被炫技干擾、評審看不到重點、司機無法在手機上有效使用。

## 決策

### 一、四個角色面向、一頁一主要對象

| 路由 | 面板 | 主要對象 | 裝置 |
|------|------|----------|------|
| `/dashboard` | 調度面板（**預設落地**） | 調派員 | 桌機 |
| `/operator` | 司機面板（保留現況、輕度整理） | 司機 | 桌機 |
| `/driver` | 司機手機端（新增） | 司機 | 手機優先 |
| `/overview` | 長官導覽面板 | 長官 | 桌機/簡報 |
| `/twin` | 數位孿生戰情室（新增） | 騎乘者／觀眾／評審 | 桌機/大螢幕 |

- 司機保有雙載具：`/operator` 桌機版維持，`/driver` 為手機優先的新面向。
- 根路由 `/` 導向 `/dashboard`。

### 二、各頁內容邊界（炫技集中戰情室）

- **調度面板**：精簡站況地圖、警示＋調度建議（預覽→確認閘門）、缺口/滿站排行、關鍵 KPI、站點抽屜（現況＋預測區間＋觸發理由）。**不放** Voronoi／Hexagon／示意路線／多屬性炫技。
- **司機面板（桌機）**：任務清單＋路線圖，維持既有行為，套一致主題。
- **司機手機端**：卡片式任務池（可接單）→ 接單後自動排程停靠序列（取/補、順序、導航、逐站回報）。
- **長官導覽面板**：宏觀 KPI、Before/After 模擬對比、回顧時間軸；不放即時操作與細站屬性。
- **數位孿生戰情室**：暗色全幅地圖、圖層控制、Voronoi／Hexagon／調度弧線、時間機器（Past/Live/Predict 播放）、站點多維資產卡、示意調度路線——所有炫技集中於此。

### 三、無捲動固定視窗版面（共同 UX 慣例）

- 各頁**頁面本身不出現捲軸**，以固定格塞滿視窗高度。
- 面板內長清單只顯示 Top-N，其餘以「查看全部」開彈窗/側欄。
- 深入資訊一律以抽屜／彈窗／次頁「點開展開」，不靠捲動。

### 四、司機手機端自動排程的決策邊界（守 ADR-004）

- 手機端「接單後自動排程」屬**操作型路徑排程（示意）**：把司機**已接的任務停靠點**用透明規則排順序，非「決定要不要派工」。
- 「要不要調度」的決策仍屬後端規則引擎；示意排程明確標示、不進派遣 payload、需人工於現場執行流程確認。

### 五、資料與範圍

- 本輪維持 **Mock-first**：接後端真預測／真緊急度／真高程屬後續決策（涉及 ADR-203 待決策的 forecast 契約，另行提案）。
- 新增 **frontend-local mock：未指派任務池**，供手機端接單流程使用；與共同 API 契約分離，不宣稱為後端契約。

### 六、承接 ADR-204 未變的決策

- 暗色戰情室設計語言與 design token；MapLibre／Deck.gl／OpenFreeMap 自帶暗色底圖、origin allowlist、no-basemap 降級、attribution、無帳務/無 key。
- React／Vite／JSX／React Router／Ant Design／ECharts／Mock-first adapter。
- ADR-203（Past/Live/Predict、固定 +30/+60、缺值不可用、不進 payload）維持不變。
- ADR-004（AI 只估計、規則引擎決策、人在迴圈）維持不變。

## 理由與判準

- 一頁一對象可大幅降低操作者認知負擔，也讓評審一眼看到炫技（集中在戰情室）。
- 無捲動固定視窗符合「戰情室/儀表板」的實務期待，資訊層次靠 drill-down 而非長捲頁。
- 司機手機端貼近真實外勤情境（行動、少互動、大按鈕）。
- 維持 Mock-first 降低本輪風險；真值接入另立決策，避免鎖死未定契約。

## 考慮過的替代方案

### 方案 A：維持三頁、只做減法
- 優點：不新增路由。
- 缺點：炫技與操作仍需共存於同頁，對象衝突無法根解；司機仍無手機面向。
- 未採用原因：無法解決「一頁服務所有人」的根因。

### 方案 B：把炫技全部移除只留操作
- 優點：最精簡。
- 缺點：失去黑客松展示與說服力。
- 未採用原因：評審是真實展示對象，炫技應集中而非刪除。

## 影響與後果

### 正面
- 各頁對象清楚、操作與展示分離；評審體驗集中於戰情室。
- 司機取得手機面向；調度面板回歸「快、準、可操作」。

### 負面與代價
- 新增兩個面向（`/driver`、`/twin`）與無捲動版面重構，前端工作量增加。
- 無捲動在小視窗需謹慎處理溢出（改用 drill-down），設計成本較高。

### 尚未解決
- 真值接入（forecast/緊急度/高程）的 API/Schema 契約（待 ADR-203 待決策項與後端協調）。
- 手機端與桌機司機頁是否長期並存，或未來以 RWD 收斂為單一面向。

## 介面與相容性

- 新增路由 `/driver`、`/twin`；`/` 落地改為 `/dashboard`。
- 頁面仍只透過 hooks／domain API modules／Mock adapter 取資料；不改後端、API、Schema 或 dispatch payload。
- 新增 frontend-local 未指派任務池 mock；不宣稱為共同契約。

## 資安與隱私

- 不新增對外請求；沿用 ADR-204 的底圖 origin allowlist 與出向邊界。
- Mock 不含真實 PII、operator/task 身分或憑證；示意排程不送派遣指令。

## 回復或取代方式

- 可移除 `/driver`、`/twin` 與無捲動版面，路由退回三頁；以新 ADR supersede 本決策，不改寫 ADR-204 或本檔歷史。

## 驗證方式

- 四面板（含手機端）在目標視窗尺寸下**頁面無捲軸**；細節以 drill-down 呈現。
- 根路由落地至調度面板；炫技視覺不再出現在調度/司機/長官頁。
- 手機端可接單並自動排出停靠序列、逐站回報；示意排程不進派遣 payload。
- `npm run build` 通過；三頁既有行為與 ADR-203／204 相容。
