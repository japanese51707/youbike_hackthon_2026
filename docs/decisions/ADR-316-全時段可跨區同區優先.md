# ADR-316：全時段可跨區、同區優先（移除不可跨區規則）

## 背景與問題

原本的班別排程對跨區有時段限制——某些班別（早／晚班）不允許一趟派工涵蓋多個行政區，只有
特定情境（如大夜、緊急）才放行跨區。可行性評估 `dispatch_feasibility._shift_reasons` 會在
不允許跨區的班別回 `cross_district_not_allowed` 阻擋確認。

owner 決定調整營運策略：**所有時段（早／晚／大夜）都允許跨區**，但安排時要以**同區優先**、
跨區次之。原本「不能跨區」的硬規則要移除。

不決策的後果：早晚班的跨區支援被硬擋，緊急站在同區湊不到車源時無法跨區補足（與 ADR-315
車源階梯相衝突）。

## 決策

**全時段允許跨區**，以「同區優先、跨區次之」為安排原則：

- `shift.allow_cross_district` **恆為真**（不再依班別限制跨區）；`_shift_reasons` 實務上不再
  產生 `cross_district_not_allowed` 阻擋。保留該函式結構以相容 config 明確設
  `allow_cross_district=false` 的特例（預設不啟用）。
- 組單挑站以**同區為主池**（被點站置頂、其餘同區站依緊急度），跨區站僅在**同區湊不足**時
  作為備援拉入（見 ADR-315 車源階梯第 3 階）。
- 一趟涵蓋多區時，`district` 標示改為「跨區」/涵蓋範圍，避免誤標單一區。

## 理由與判準

- **營運彈性**：全時段可跨區讓車源／人力在同區不足時能跨區支援，提高調度成功率。
- **與車源階梯一致**：ADR-315 的「同區湊不足→跨區取一站補足」需要跨區被允許；本 ADR 移除
  硬擋讓該階梯生效。
- **同區優先仍保留**：透過挑站排序（同區主池、跨區僅備援）落實，非靠硬擋，避免過度長程跨區。
- **可逆**：保留 `allow_cross_district` 的 config 開關結構，未來要恢復某班別禁跨區仍可設定。

## 考慮過的替代方案

### 方案 A：全時段允許跨區、以排序落實同區優先（採用）

- 優點：彈性高、與車源階梯一致、同區優先仍在、可逆。
- 缺點：可能出現較長程的跨區支援（已由「同區優先、跨區僅備援」緩解）。
- 未採用原因：無——採用方案。

### 方案 B：維持班別跨區限制

- 優點：限制長程跨區。
- 缺點：與 owner 決策及 ADR-315 車源階梯相衝突，緊急站無法跨區補車源。
- 未採用原因：owner 明確要求移除不可跨區規則。

## 影響與後果

### 正面

- 早晚大夜皆可跨區支援；車源／人力調度更有彈性，緊急站更易補到車源。
- 同區優先透過排序保留，不會無謂地優先跨區。

### 負面與代價

- 跨區支援可能增加移動距離／時間（由同區優先排序與可行性工時檢查緩解）。

### 尚未解決

- 未針對跨區距離設上限；目前靠緊急度與工時可行性自然約束。

## 介面與相容性

- **行為**：`shift.allow_cross_district` 恆真（除非 config 明設 false）；`_shift_reasons`
  不再擋跨區。組單挑站排序落實同區優先。
- **相容性**：確認可行性其他檢查（載量守恆、逐站視野、工時、重疊）不變；跨區多區趟的
  `district` 標「跨區」。
- **設定**：保留 `allow_cross_district` 開關（預設允許）。

## 資安與隱私

- 無新增對外邊界；純調度規則調整。不涉個資。

## 回復或取代方式

- 於 config 設 `allow_cross_district=false`（或恢復班別條件）即可回到限制跨區；未來策略變更
  以新 ADR supersede。

## 驗證方式

- 可行性測試：跨區趟在各班別不再被 `cross_district_not_allowed` 阻擋。
- 組單測試：同區優先排序、跨區僅在同區湊不足時備援拉入（配合 ADR-315）。
- 後端全套測試僅餘 pre-existing 失敗（與本次無關）。
