# ADR-307：競賽現場雲端部署與 S3 遷移（us-east-1 / ECS Fargate / 金鑰雲端化）

## 背景與問題

競賽現場開放主辦方 AWS 環境（新帳號 053134152077、臨時 assumed-role 憑證、指定區 us-east-1/us-west-2）。
原資料 bucket `youbike-hackathon-2026` 在團隊原帳號的東京區（ap-northeast-1）。

痛點與限制：
- **金鑰空白痛點**：他人從 GitHub 拉專案時，`.env`（含 CWA 天氣金鑰等）不進版控，本機後端讀不到金鑰
  → 天氣等功能失效。不能要求每個使用者自備金鑰。
- **依賴本機**：後端跑在開發者本機，關機即中斷，無法讓評審隨時連上。
- **規範**：主辦規範要求新建資源放 us-east-1/us-west-2、S3 不可公開、不對外全開、憑證不進版控、
  `/.kiro` 必須進版控、不建議大規模訓練（見 `.kiro/steering/aws_competition_rules.md`）。

不決策的後果：demo 時資料/金鑰接不上、系統綁在單一台電腦。

## 決策

在競賽現場帳號（us-east-1）建立雲端部署，讓「拉 GitHub 前端即可用、金鑰在雲端、本機關機不影響」：

1. **S3 遷移**：在 us-east-1 建專屬 bucket `youbike-hackathon-2026-use1`（開啟 Block Public Access），
   將 1–6 月歷史 Parquet（110MB）遷入；後端 `config.yaml` 的 `s3_bucket` 指向新 bucket。
2. **後端部署 ECS Fargate**：`backend/Dockerfile` 改自包含（打包 config.yaml）→ ECR image →
   ECS Fargate service（public IP、Security Group 只開 8000、非對外全開）。
3. **金鑰雲端化**：CWA 等金鑰以 ECS task definition 環境變數注入（不寫進 image/版控）；
   讀 S3 靠 task role（`youbike-ecs-task`，最小權限、限該 bucket），不用長期金鑰。
4. **前端連線**：前端走 Vite proxy（`VITE_API_BASE_URL=/api/v1` → `YOUBIKE_BACKEND_URL` 指向雲端後端），
   proxy 為 server-side 同源，免改 CORS。
5. **SageMaker 定位**：即時單站推論仍由後端服務跑；SageMaker 用於「批次推論示範」與未來「每日重訓管線」，
   按需啟動、跑完自動關（見 ADR-306 的批次推論、`backend/sagemaker/`）。不在雲上重訓大模型（守規範）。

## 理由與判準

- **解痛點**：金鑰集中在雲端後端，使用者零設定即可連，天氣/資料/預測都正常。
- **規範相容**：資源在 us-east-1、S3 非公開、SG 只開必要埠、憑證走環境變數/role、不大規模訓練。
- **可交付**：ECS Fargate 用現有 Dockerfile 不改程式；App Runner 被主辦 SCP 擋（`apprunner:*` 拒絕），
  ECS 為權限測試可行且最貼近本機的方案。
- **成本可控**：Fargate 最小規格（0.25 vCPU/0.5GB）約 US$10/月，賽後關閉。

## 考慮過的替代方案

### App Runner
- 優點：最簡單（給 image 自動配 HTTPS 網址）。
- 缺點：被主辦組織 SCP 封鎖（`no service control policy allows apprunner:*`）。
- 未採用原因：現場環境不允許。

### Lambda + API Gateway
- 優點：成本最低、閒置零費用，最符合資源節制。
- 缺點：需改程式（Mangum）、冷啟動、S3 建表 12 秒與 15 分鐘上限需處理。
- 未採用原因：比賽時程下不值得為此改動與冒風險。

### 單一 EC2
- 優點：最像本機。
- 缺點：要自管機器、常駐計費、SG 需嚴管。
- 未採用原因：ECS Fargate 免管機器、更貼近容器化最佳實務。

## 影響與後果

### 正面
- 任何人 `npm install && npm run dev` 即連雲端後端，零金鑰設定；本機關機不影響。
- 資料在指定區、符合規範；金鑰不進版控、走最小權限 role。

### 負面與代價
- Fargate task 的 public IP 為臨時，task 重啟會變，需更新 `frontend/.env` 的 `YOUBIKE_BACKEND_URL`
  （要固定網址需 ALB，成本較高，比賽階段不做）。
- 現場憑證為臨時 assumed-role，過期後無法重部署（已跑的 service 仍運作），需重貼新憑證。
- Fargate 常駐有費用，賽後須刪 service/cluster。

### 尚未解決
- 前端本身尚未上雲 host（目前使用者本機跑前端連雲端後端即可）。
- 固定網址（ALB/HTTPS）留待需要時再加。

## 介面與相容性

- `config.yaml` `data_source.s3_bucket` → `youbike-hackathon-2026-use1`；`.env` `AWS_REGION=us-east-1`。
- `backend/Dockerfile` 改為專案根 context 自包含（`YOUBIKE_CONFIG_PATH=/app/config.yaml`）；新增根 `.dockerignore`。
- `frontend/.env.example` 的 `YOUBIKE_BACKEND_URL` 指向雲端後端。
- 雲端資源：ECR `youbike-backend`、ECS cluster `youbike` / service `youbike-backend` /
  task def `youbike-backend`、SG `sg-09e0635d293224992`（只開 8000）、
  IAM `youbike-ecs-execution`/`youbike-ecs-task`/`youbike-sagemaker-exec`、log group `/ecs/youbike-backend`。

## 資安與隱私

- S3 開 Block Public Access；SG 只開 8000（非對外全開）。
- 金鑰以環境變數注入容器，不進 image/版控；`.env`、`frontend/.env` 均 gitignore。
- 讀 S3 走 task role 最小權限（限該 bucket 唯讀）；不使用長期 access key。
- 現場臨時憑證僅用於建置，服務運行靠附加 role。

## 回復或取代方式

- 關閉雲端：`aws ecs update-service --desired-count 0` → 刪 service/cluster/task-def；
  前端 `YOUBIKE_BACKEND_URL` 改回 `http://127.0.0.1:8000` 即回本機模式。
- 資料源可切回原 bucket（改 `config.yaml`）。以新 ADR supersede，不改寫本 ADR。

## 驗證方式

- 雲端後端直連 `http://<public-ip>:8000`：health OK、站點 1606、CWA 天氣真實、預測 ready。
- 前端 dev 經 proxy → 雲端後端：站點/天氣/預測全通，使用者未輸入任何金鑰。
- SageMaker 批次推論 job 完成並產出 `s3://.../sagemaker/batch-predict/output/predictions.json`。
