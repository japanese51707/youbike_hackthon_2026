# ADR-332：雲端經 S3 中繼讀官方站況（繞過境外 IP 封鎖）

## 背景與問題

雲端 ECS（us-east-1 境外 IP）直連台灣官方 `data.ntpc.gov.tw` 抓站況，實測穩定失敗：
先 `ReadTimeout`（跨海讀 404KB 超過 10s），後 `ConnectError('[Errno 101] Network is unreachable')`。
AWS 這端網路設定全正常（主路由表 0.0.0.0/0→IGW、task 有 public IP、SG 出向全開），
且本機（台灣出口）直連官方正常（1606 站、0.6s）——確認是**官方端封鎖境外/雲端 IP**。
拉大 timeout 無效（封包出不去）。站況 503 連帶 recommendations / 自動配單全掛。

## 決策

採 **B 方案：台灣端中繼 → S3 → 雲端讀 S3**（解耦，不依賴雲端直連官方）。

1. **中繼**（`tools/relay_stations_to_s3.py`，跑在能連官方的台灣機器，demo 期間 owner 本機）：
   定時（預設 120s）抓官方 CSV → 驗證（解析出 ≥500 站才算有效）→ 原封上傳
   `s3://<bucket>/live/stations_latest.csv`。抓取失敗跳過本輪（不覆蓋 S3 上一份好資料）。
2. **雲端資料源**（`youbike_s3`，繼承 `YouBikeOfficialDataSource` 只覆寫 `_fetch_raw`）：
   從同帳號 S3 讀該 CSV（走 task role s3:GetObject，快且不受官方封鎖），其餘解析／驗證／
   快取／退避／欄位轉換全複用官方源，產出一致的標準站況格式。
3. **新鮮度保護**：S3 物件 LastModified 超過 `s3_max_age_sec`（預設 900s=15 分）視為過期
   （中繼掛掉不供應過期資料，交由 degradation 走 stale 快照或 503）。
4. config `data_source.mode` 改 `youbike_s3`（本機開發要直連官方即時可臨時改回 youbike_official）。

## 理由與判準

- 官方封鎖境外 IP 無法從雲端側解；台灣中繼是這類「雲端在境外、資料源在台灣」的標準解法。
- 繼承官方源只換資料入口，確保兩者站況格式一致、維護面最小。
- 讀 S3 走 task role（既有 s3-read-youbike policy 已涵蓋 bucket/*），不新增對外邊界。

## 考慮過的替代方案

- (A) S3 歷史資料當備援：非即時，不符 owner「要即時數據」。
- (C) 讓雲端能連官方：官方封鎖境外 IP，走不通。
- (D) 前端直接連本機後端：demo 依賴本機、且未上雲。B 兼顧即時與上雲，故採 B（D 為最後備案）。

## 影響與後果

- 正面：雲端站況即時恢復、不受官方封鎖；自動配單／建議全復原。
- 代價：**demo 期間台灣端中繼必須持續運作**（本機開著）；中繼掛掉超過 15 分鐘雲端會 503。
- 尚未解決：中繼目前跑在本機（非常駐服務）；賽後若要長期運作可移到台灣的常駐 VM。

## 介面與相容性

- 新增 `core/data/youbike_s3.py`、工廠 `_build` 註冊 `youbike_s3`、`tools/relay_stations_to_s3.py`。
- config 新增 `live_s3_key`、`s3_max_age_sec`；mode 改 youbike_s3。
- 標準站況欄位不變；上層（規則引擎/API）無感。

## 資安與隱私

- 讀 S3 走 task role 最小權限（GetObject/ListBucket，限該 bucket）；中繼上傳走本機 AWS 憑證。
- 只傳站況（非個資）；S3 維持 Block Public Access（規範第 1 條）。

## 回復或取代方式

- config mode 改回 `youbike_official` 即回直連（在能連官方的環境）。中繼可停。

## 驗證方式

- 中繼 --once 上傳成功（1606 站）；youbike_s3 讀回 1606 站格式正確；雲端部署後 stations 200、
  recommendations 200、自動配單恢復配單。
