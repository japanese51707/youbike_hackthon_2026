# ADR-008：依賴釘選與決策關鍵行為測試

> 追溯說明：accepted 表示 owner 已核准本次補記的決策邊界；歷史事實以列出的 commit／程式為準。下列替代方案是事後取捨分析，不表示當時曾逐項討論，例如「不更新依賴」只代表不採用的未來維護策略。

## 背景與問題

黑客松交付需要在不同開發機與容器重現。若使用開放版本範圍，套件更新可能在 Demo 前改變 FastAPI、Pydantic、bcrypt 或資料處理行為；若只做端到端手測，最重要的規則、權限與 Schema 回歸很難定位。

## 決策

- 後端 runtime 與 dev dependencies 使用精確版本釘選。
- 容器以 Python 3.12 作為可重現的後端執行基線。
- 測試優先固定「影響決策正確性或安全邊界」的行為：Schema、規則引擎、覆寫、權限與 API 安全。
- 測試使用 Mock 與記憶體 SQLite，避免依賴 AWS、真實 API 或其他角色尚未完成的模組。
- 依賴升級視為受控變更：先驗證相容性，再更新釘選；重大框架／執行期變更需重新評估 ADR。

## 理由與判準

- 精確版本讓本機、CI 與 Docker 行為一致。
- 模組化測試能快速指出是契約、規則或權限失敗。
- 核心決策測試的價值高於追求表面覆蓋率。
- 離線測試不受 AWS 憑證與第三方可用性影響。

## 考慮過的替代方案

### 使用未釘選或寬鬆版本範圍

未採用：安裝時間不同可能取得不相容版本，難以重現 Demo。

### 只做完整端到端測試

未採用：前端、模型與即時源尚未完成，且失敗定位慢。

### 不更新依賴

未採用：釘選不是永久凍結；安全與相容性更新仍需定期、可驗證地進行。

## 影響與後果

### 正面

- 開發與部署環境較可重現。
- ADR-004、ADR-007 等不可違反行為有回歸保護。
- 測試可在沒有外部服務時執行。

### 負面與代價

- 需要主動維護安全更新與 Python 相容性。
- 單元／契約測試不能取代真實資料整合、負載與部署測試。

### 尚未解決

- Repo 尚未宣告單一機器可讀的 Python 最低版本；現行釘選中的 pandas 需要 Python 3.11 以上，而 Docker 基線為 3.12。
- 前端尚未建立，因此沒有 Node／前端依賴策略。
- CI pipeline 尚未由此歷史群組證明。

## 介面與相容性

`requirements.txt` 是 runtime 依賴，`requirements-dev.txt` 在其上加入測試工具。升級 Pydantic、FastAPI、bcrypt、pandas 或 pyarrow 時，需跑相關契約與資料測試。

## 資安與隱私

釘選降低非預期供應鏈變動，但也可能延後安全修補；維護者必須定期檢查漏洞，且不得用跳過驗證或來源不明套件換取安裝成功。

## 回復或取代方式

依賴升級可回復到上一組已驗證釘選。若改用 lockfile／uv／Poetry，建立新 ADR 說明單一依賴來源、平台解析與遷移方式。

## 驗證方式

- 在 Python 3.12 的乾淨環境安裝 runtime/dev requirements。
- 執行最窄相關 pytest，確認規則、Schema、權限與安全行為。
- 建置 backend Docker image。
