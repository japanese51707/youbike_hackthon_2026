# ADR-012：擴充預測特徵（時間衍生 / POI 距離 / 事件 / 特殊天氣）

## 背景與問題

ADR-011 已定初期四因子（假日/學生數/天氣/地形）並完成實作。經與 owner 討論，確認還有多類影響 YouBike 借還需求的因子未納入。本 ADR 承接 ADR-011（不取代），新增第二批因子與其資料源、實作方式。不決定的後果：這些因子散落或臨時硬接，無法系統化評估貢獻。

## 決策

新增下列因子，各自獨立模組（延續 ADR-011 一因子一檔原則），單因子先行、暫不做交叉：

1. **時間衍生因子** `time_features.py`（A 類，零外部資料）：從 timestamp 衍生「小時、是否通勤尖峰(07-09/17-19)、星期幾、是否週末、月份、季節」。

2. **POI 距離因子** `poi_distance.py`（B 類）：標注 10 類地理靜態 POI 的座標，計算每個 YouBike 站到「最近各類 POI」的距離。
   - POI 類型：捷運站、火車站、公車轉運站、學校、商場、夜市、醫院、公園、河濱、表演展覽場地
   - 資料源：OpenStreetMap Overpass API（實測可查含座標），抓取後存本地 POI 資料檔（靜態、進版控）

3. **站點區域類型** = POI 距離的衍生輸出（不獨立人工標 1576 站）：站點類型由「最近且在門檻內的 POI 類別」自動判定（如 100m 內有捷運→transit，最近是學校→school，靠河濱→leisure）。門檻可 config 調。

4. **事件因子** `event_impact.py`（C 類，選項 A：介面先行）：建「事件資料表」（活動/路跑/馬拉松，含日期、地點座標、預估規模、影響半徑），訓練歷史資料事後補、現場可填。對齊 design 既有 event 影響規劃與 parameter_groups。

5. **特殊天氣因子** `weather_alert.py`（D 類）：颱風、豪大雨特報、停班課等「異常日」標籤。呼應 model_architecture「異常日標籤化」——這類日子既要能在訓練時排除（避免教壞模型），也保留當「特殊情境預估」依據。初期用規則（雨量/風速閾值）+ 可手動標註的停班課日表。

## 理由與判準

- **時間衍生零成本、高價值**：尖峰/星期/季節是需求預測最基本且強的訊號，從既有 timestamp 就能算
- **POI 抽象比單看捷運通用**（owner 洞見）：站點需求受多種鄰近設施影響，用「到各類 POI 距離」統一表達
- **區域類型自動推導**：避免人工標 1576 站的主觀與工作量，且新站可自動歸類
- **事件介面先行**：事件是動態逐次資料，無現成歷史 API，先建結構、資料後補（選項 A）
- **特殊天氣對齊既有異常日設計**：訓練排除 + 情境預估兩用途，model_architecture 已有此構想

## 考慮過的替代方案

### 站點區域類型：人工/官方標注 1576 站
- 優點：可能更精準
- 缺點：工作量大、主觀、新站要重標
- 未採用原因：POI 自動推導更一致可維護（可保留人工覆寫為未來選項）

### 事件因子：訓練前先爬歷史活動清單（選項 B）
- 優點：訓練期就有事件特徵
- 缺點：歷史活動清單分散難蒐集，投報率低
- 未採用原因：owner 選介面先行、資料後補；不阻塞其他因子

### POI 資料源：Google Places API
- 優點：資料新、分類細
- 缺點：需金鑰、有費用、有配額
- 未採用原因：OSM Overpass 免費免金鑰已足夠（避免金鑰管理，呼應 steering §11.1）

## 影響與後果

### 正面
- 特徵涵蓋時間/空間/事件/極端天氣四個維度，預測更完整
- 各因子可獨立評估 feature importance

### 負面與代價
- OSM 資料完整度依賴社群維護（某些 POI 可能缺漏，需驗證）
- Overpass 公用伺服器可能超時（504）→ 抓取後存本地快取/資料檔，不即時查
- 事件與停班課的歷史資料需事後補齊才有訓練價值

### 尚未解決
- 交叉影響（雨天×尖峰×假日×活動）仍留待後續 ADR
- 事件影響半徑/規模→需求的轉換係數待校準（同 ADR-011 粗估後校準）
- 特殊天氣閾值（多大雨算豪大雨）待定，先用中央氣象署特報標準當預設

## 介面與相容性

- 新增 `backend/features/` 下數個模組，輸出特徵欄位供訓練/推論
- POI 與事件資料以本地資料檔（JSON）存放，靜態部分進版控、抓取快取不進版控
- 不改 `core/interfaces.py` 的 PredictionInterval（延續 ADR-011）

## 資安與隱私

- OSM 為公開開放資料，無個資
- Overpass 為出向請求：設超時、失敗不阻塞（抓不到用既有本地資料）、視為不可信輸入驗證格式
- 不引入需金鑰的第三方（POI 用 OSM 免金鑰）

## 回復或取代方式

- 各因子模組可獨立停用（模型退回不含該特徵）
- 設計變更以新 ADR supersede，不改寫本 ADR

## 驗證方式

- 各因子單元測試（給定 timestamp/座標/日期 → 正確特徵值）
- POI 距離：抽查已知站點到捷運/學校距離合理
- 模型層：比較「含新因子 vs 不含」的 MAE 與區間覆蓋率、feature importance
