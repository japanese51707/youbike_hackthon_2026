# ADR-116：調度角色與班別模型

## 背景與問題

ADR-114 建立了「調度資源清單（人員/車輛）+ 行政區任務指派」的基礎，但把所有調度人員視為同質，
且假設「一趟任務不跨行政區」為全域鐵律。與 YouBike 實際營運對照後，發現組織更細緻：

- 人員分兩種角色，職責與空間特性完全不同（點對點運送 vs 固定站駐守）。
- 調度車人員分三班，各班策略不同；**大夜班需要跨行政區調度**，與 ADR-114「一趟不跨區」衝突。
- 還有「後台管理人員」——調度中心的決策者，是本系統的主要使用者。
- 有勞基法工時約束（連續 4 小時須休息）。

這些是後續排程策略（ADR-117）、駐點與預備車（ADR-118）的共同基礎，需先定義清楚。

歷史資料佐證（docs/analysis/dispatch_ops_analysis.md）：早尖峰折返 ≈39 台、晚尖峰 ≈38 台（≈官方41車）；
駐點熱點前 15 名清一色捷運大站；尖峰後工作量斷崖下降。營運模型與真實運作吻合。

## 決策（proposed，待 owner 核准）

### 一、三種調度角色

| 角色 | 職責 | 空間特性 | 資源綁定 |
|------|------|---------|---------|
| **調度車人員**（driver） | 點對點車輛運送（把車從 A 站搬到 B 站） | 跨站移動 | 綁一台調度車（vehicle） |
| **駐點人員**（stationed） | 固定熱門站現場拉/放車（尖峰保證可借可還） | 綁定單一站 | 綁一個站 + 該站駐點預備車 |
| **後台管理人員**（controller） | 派遣、看進度、安排下一步（決策台使用者） | 不在現場 | 無（操作系統） |

- driver 用既有 vehicles + 派工單邏輯（ADR-114）。
- stationed 是**新概念**：不「跑」，守在一個站，用該站預備車即時調節（機制細節在 ADR-118）。
- controller 是本系統主使用者，系統對他呈現全局、供他派遣與監控。

operators 表加 `role_type`（driver/stationed/controller）與（stationed 專用）`stationed_at`（駐守站）。
既有 `role`（operator/dispatcher/maintainer）為登入權限角色，與此營運角色 `role_type` 正交，兩者並存。

### 二、調度車三班制（班別決定策略）

| 班別 | 代表時間（可配置） | 涵蓋尖峰 | 跨區 |
|------|-----------------|---------|------|
| **早班**（morning） | 06:30–15:30 | 早尖峰 07:30–09:30 | 否（限本區） |
| **晚班**（evening） | 16:00–22:00 | 晚尖峰 17:00–19:00 | 否（限本區） |
| **大夜班**（night） | 22:00–翌日 06:30 | 無 | **是（可跨區）** |

- 班別時間放 config（`shifts`），**自動延伸到相鄰班無縫銜接**（早班收班=晚班上班；大夜接晚班尾、交早班頭），
  避免出現無人覆蓋的空窗（owner：實際班表未知，先設為連續覆蓋）。
- 班別策略差異（尖峰折返 / 離峰效率最大化 / 大夜跨區大宗復原）詳見 ADR-117。

### 三、跨區約束改為「班別相關」（修正 ADR-114 的全域鐵律）

- **早/晚班**：一趟任務不跨行政區（維持 ADR-114 原約束）。
- **大夜班**：解除跨區限制，可執行跨區大宗復原與長距離調度。
- 實作：跨區約束不再寫死，改為依「當前班別」查 config 的 `shifts.<班別>.allow_cross_district`。
- 本 ADR 就此點**部分修正 ADR-114**（不 supersede 整份，僅將「不跨區」從全域改為早/晚班限定）；
  ADR-114 加註指向本 ADR。

### 四、勞基法工時約束與工作警示

- 硬約束：連續工作 4 小時必須休息 ≥ 30 分（config `labor.連續工時上限_分鐘=240`、`labor.休息時間_分鐘=30`）。
- **工作警示系統**：追蹤每人累計連續工時（既有 operators.today_work_minutes + 連續工時計算），
  接近上限時預警「下次任務建議 N 分後、應安排休息」，並在派遣時**排除已達工時上限者**。
- 這是「示警與反應速度」核心之一（與排程同等重要，見題目宗旨），細節（警示分級/通知）於 ADR-118 警報段統整。

### 不改
- ADR-114 的車輛/人員主檔結構（僅 operators 擴 role_type/stationed_at）、Provider 可抽換、行政區為任務約束的框架。
- ADR-115 動態目標水位、ADR-111/112/113 規則/緊急度/預測。

## 理由與判準

- **對準真實營運**：兩角色 + 三班 + 後台管理者是 YouBike 實際組織，系統貼合才可商用可信任。
- **解除大夜跨區衝突**：把「不跨區」從全域鐵律降為「班別相關約束」，既保留白天分區效率，又允許夜間大宗復原。
- **工時合規**：勞基法是硬約束，不可違反；工作警示同時服務「合規」與「反應速度」。
- **參數外部化**：班別時間、跨區開關、工時上限全進 config（steering §3）。
- **向後相容**：operators 擴欄、約束改查 config，既有邏輯不破壞。

## 考慮過的替代方案

### 所有調度人員同質（維持 ADR-114 現況）
- 缺點：無法表達駐點 vs 跑車、無法差異化班別策略、大夜跨區無解。未採用。

### 大夜跨區用「特例繞過」而非班別約束
- 缺點：硬寫特例難維護、其他班別若也要調整無彈性。未採用，改為班別相關的 config 開關。

### 駐點人員也綁車（比照 driver）
- 缺點：駐點的本質是「守站用現場預備車」，綁車反而混淆。未採用，駐點綁站不綁車。

## 影響與後果

### 正面
- 角色/班別/工時模型完整，為 ADR-117 排程策略、ADR-118 駐點預備車奠基。
- 大夜跨區衝突解除；工時合規有系統保障。

### 負面與代價
- operators 擴欄（role_type/stationed_at）+ config 加 shifts/labor 區塊。
- 跨區約束改為查 config（dispatcher assign_by_district 需依班別判斷）。

### 尚未解決
- 班別排程策略（尖峰折返/離峰效率/大夜跨區的演算法）→ ADR-117。
- 駐點預備車量、緊急救火、死結警報、即時天氣 → ADR-118。
- 實際班表時間（用 config 預設連續覆蓋，待 YouBike 提供真實班表覆蓋）。

## 介面與相容性

- operators 表加 `role_type TEXT`（driver/stationed/controller）、`stationed_at TEXT`（駐點站，僅 stationed）。
  用 connection.py 輕量 migration（比照 ADR-114）。既有列該欄 NULL，向後相容。
- config 新增 `shifts`（三班時間 + allow_cross_district）、`labor`（工時上限/休息）。
- dispatcher 跨區判斷改依班別（介面不變，內部邏輯調整）。
- ADR-114 加註「跨區約束由 ADR-116 改為班別相關」。

## 資安與隱私

- role_type/stationed_at 非敏感；駐點人員若含真名比照 operators 現有 PII 處理（seed 用編號）。

## 回復或取代方式

- 移除擴欄與 config 區塊、跨區判斷改回全域即回復；改方向以新 ADR supersede。

## 驗證方式

- operators 擴欄 migration 冪等（缺欄舊 DB 補得上）。
- 班別判斷：給定時間點回傳正確班別；相鄰班無縫銜接（無空窗）。
- 跨區約束：早/晚班不跨區、大夜可跨區（依 config）。
- 工時：連續工時達上限者被排除派遣；跑既有測試不破壞。
