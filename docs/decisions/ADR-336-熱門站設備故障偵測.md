# ADR-336：熱門站設備故障偵測（車故障／柱故障）

## 背景與問題

熱門站在尖峰流量大時，正常應該有機會被借到接近全空或還到接近全滿。若一個熱門站在尖峰
的近半小時內，可借車數（或可還位）一直卡在某個下限值、始終碰不到全空/全滿，很可能有
設備故障把車或柱卡死——但系統只看即時數字，會把「卡住的殘值」當成正常庫存，導致該站
風險被低估、永遠偵測不到、也不會被調度。

## 決策

新增熱門站設備故障偵測，三重保守條件降低誤判：

1. **熱門站**：站×當前小時的歷史周轉量 ≥ 全市 **P90**（`station_hour_turnover.json`；只看最
   活躍的大站，因為只有它們尖峰「本該」碰到極值。owner：車不多，門檻取嚴）。
2. **足夠序列**：近 30 分鐘的站況快照 ≥ 5 筆（`station_snapshots_repo`，官方 5 分一筆≈6 筆）。
3. **卡住**：視窗內可借/可還變化 ≤ 容差（預設 2 台）且從沒碰到極值。

**車故障 vs 柱故障**（比較卡住那端離極值多近，避免互相誤判）：
- **車故障**：站偏空側卡住——可借車數卡在下限 L 借不走（L 台疑似壞車鎖住）。故障數＝L。
- **柱故障**：站偏滿側卡住——可還位卡在下限 M 還不進（M 個疑似壞柱）。故障數＝M。

**扣除故障後重算**（owner 定案「扣一個」）：
- 車故障 L：`available_bikes −= L`、`total_docks −= L`（L 柱被壞車佔住不能用）。
- 柱故障 M：`total_docks −= M`、`available_docks −= M`（M 個壞柱還不進）。
- 重算 `usage_rate` 與 `status`（classify_status）；原始值存 `raw_*` 供顯示「原本 → 扣除後」。

**進調度決策（緊急度）**：扣除故障後站況更接近空/滿 → 緊急度自然上升。以「扣除後站況」重算
緊急度，並與「原始站況」算的分數取 **max**（保底——故障偵測只抬升、不壓低緊急度）。
如此有故障車卡住的站不會再被當成沒風險而永遠漏掉。

**任務單顯示**：派工單 route 帶 `suspected_fault`/`fault_type`/`fault_count`，前端組單預覽
（OrderBuilder）與進行中任務（DispatchStatusPage）在該站顯示「疑似 N 台車故障・可順道取回／
N 個柱位故障」，提示調度員取回故障車。

注入點：`degradation.get_stations_with_degradation` 主入口（唯一站況總入口）——單點注入，
同時生效於顯示、空滿率（KPI）、緊急度（dispatcher）、任務單。放在空滿時計 sync 之後，
讓時計看「原始站況」、故障扣除只影響調度/顯示/KPI，不誤觸時計。

## 理由與判準

- 三重保守（熱門 P90 + 足夠筆數 + 卡住不動）大幅降低誤判；「疑似」措辭保留不確定性。
- 扣除後重算取 max 而非硬加分——真實反映「扣掉故障後這站其實更危險」，且不會反向壓低緊急度。
- 單點注入於站況總入口，維護面最小、覆蓋最全。

## 考慮過的替代方案

- 對緊急度「外加固定分數」：owner 認為不如「扣除後重算」真實；且外加分數易失真。未採用。
- 用 observations 記憶體序列判定：只有 available_bikes、無 docks，算不了柱故障。改用
  station_snapshots_repo（欄位齊全、可 since 過濾）。

## 影響與後果

### 正面

- 熱門站被故障卡住的隱性風險被揭露並進調度；空滿率排除故障後更準；任務單提醒取回故障車。

### 負面與代價

- 「疑似」仍可能誤判（如尖峰剛好平穩）；已用三重條件與 max 保底緩解，且措辭標「疑似」。
- 依賴 station_snapshots_repo（隊友 ADR-328 的 24h 快照庫）；該庫不可用時偵測靜默跳過。

### 尚未解決

- 故障數量為「卡住殘值」估計，非精確判定；未與官方維修回報交叉驗證。

## 介面與相容性

- 新增 `core/fault_detection.py`（`is_hot_station` / `detect_fault`）。
- `degradation` 注入 `_apply_fault_detection`；站況 dict 增 `suspected_fault`/`fault_type`/
  `fault_count`/`fault_reason`/`raw_total_docks`/`raw_available_bikes`/`raw_available_docks`。
- `dispatcher.build_dispatch_list` 對故障站取 max 緊急度並帶 fault 到 rec；
  `_persist_trip_atomic` route 帶 fault 欄位。
- 前端 OrderBuilder / DispatchStatusPage 顯示故障提示。
- config 新增 `fault_detection` 區塊（enabled/熱門周轉門檻/視窗分鐘/最小筆數/卡住變化容差）。
- 相容性：無故障站（或 mock 無序列）時行為完全不變；欄位皆為新增。

## 資安與隱私

- 只讀既有站況序列，不新增對外邊界；不涉個資。

## 回復或取代方式

- config `fault_detection.enabled: false` 即完全關閉（站況回原始值）。以新 ADR supersede 調整判準。

## 驗證方式

- `tests/test_fault_detection.py`：車故障（卡低可借）、柱故障（卡低可還）、碰到極值不判、
  變化大不判、序列不足不判、非熱門不判、車柱互不誤判，皆通過。
- 後端全套測試無回歸；前端 build 通過。
