# ADR-302：派工確認與任務結案一致性

## 背景與問題

2026-09-11 程式審查及隔離測試確認：緊急檢查可直接修改車輛狀態；確認信任呼叫者提供的草稿；同一人車與站點可被重複指派；任務、資源、稽核各自提交；非指派人員可回報非法存量；逐站完成未連動結案與資源釋放。

## 決策

沿用 ADR-004、007、009、010、114、116、117、118、119。本決策補齊既有人工確認、認領與結案約束，SQLite 單實例及 Demo 身分機制不變。

1. 三個組單入口由後端保存短期記憶體草稿，含不可猜測的 ID、版本、期限與建立者；未確認不占用資源。修改選項須重新組單取得新預覽。確認使用 ID／版本；相容的完整草稿必須與後端保存內容一致，不能覆寫後端內容。
2. 確認需 dispatcher／maintainer 權限，重新驗證草稿期限、人車存在／啟用／可用狀態、執行人員營運角色、站點認領及既有容量約束。過期、竄改及資源衝突回 409；非法輸入回 422；無身分／權限回 401／403。
3. 確認收據與 task、人車占用、稽核在同一個 SQLite `BEGIN IMMEDIATE` 交易內提交；任何一步失敗全部回滾。收據在確認後才持久化，同一草稿版本重送回原任務，重啟後亦不重派。Repository 使用共用交易連線，內層不提前 commit。
4. 緊急檢查只回建議，不派車；`persist=true` 明確拒絕，正式緊急派遣使用三入口中的 emergency 預覽及共同確認。這落實 ADR-004 的人工閘門，ADR-118 的警報與備援資源規則繼續適用。
5. 指派人員才可開始、回報及退回自己的任務。回報量為有限、非負整數，有站容量時不得超過容量。首次合法回報可相容地開始 assigned 任務；另提供明確 start 入口。已完成／移除站點不得覆寫，完成或取消的任務不得再執行。
6. 所有站點均已回報或移除時，依合法狀態轉換完成任務；取消／執行者退回亦清除站點認領並釋放所屬人車。僅清除仍指向該任務的資源，避免舊任務釋放新任務；預備車恢復派出前 standby 狀態。執行中退回維持 manual_required，未開始退回為 cancelled。
7. 後台增減站點仍需角色授權、任務狀態及認領檢查。來源覆寫到期所造成的取消也走同一資源釋放流程；結案不把其他後續覆寫一併刪掉。

## 理由與判準

人工確認必須作用於後端已知的預覽；重新檢查與寫入必須不可分割；驗證回報、結案與資源狀態必須一致。保留現有框架及資料庫可降低這批修正的遷移範圍。

## 考慮過的替代方案

- 只加前端按鈕鎖：無法防直接 HTTP 呼叫、重送與並行確認，不採用。
- 各 Repository 分別提交：中途失敗無法保證一致性，不採用。
- 換 PostgreSQL／Redis／正式認證：超出本次核准範圍，且不是修正上述問題的必要條件。

## 影響與後果

正面：派遣可追溯、防止重複占用，失敗可重試，結案後資源可再次派遣。

代價：草稿增加有限期限及單程序限制；舊客戶端須保留 build 回傳的版本，修改內容後重新預覽；過去接受的非法回報將被拒絕。既有歷史任務保留，不自動刪除或推測其完成狀態。

尚未解決：真實資料新鮮度、多視野 ETA、逐站載量守恆、模型評估及前端正式整合，依審查的後續批次處理。本批容量檢查沿用現行保守總量規則，不宣稱已完成路線載量模型。

## 介面與相容性

新增確認收據表，使用 IF NOT EXISTS 初始化；既有表採可重複擴欄。新增草稿期限／數量上限設定。API 契約文件同步 request、錯誤及狀態語意。舊的 mock `/dispatch/confirm` 不再假裝完成派工，改共用草稿確認契約。

## 資安與隱私

角色由後端查詢；不信任 client 的任務、人車或回報欄位。不新增真實個資、憑證、外部服務呼叫或自動實體動作。ADR-010 的可偽造 header 限制仍限受控 Demo。

## 回復或取代方式

新增資料表與欄位可保留，撤回應先停用寫入端點，不能重新開放已知繞過。需要改變交易、草稿儲存或正式認證時另立 ADR。既有任務異常由管理者核對，不進行破壞性自動修復。

## 驗證方式

使用記憶體及暫存 SQLite 驗證：未授權／越權操作、草稿竄改／過期／重送、兩個草稿競爭相同人車或站點、中途寫入失敗回滾、非法數量、非指派者回報、終態重報、全部回報結案、退回及覆寫取消釋放資源。測試隔離資料來源及模型，不存取正式資料庫。

執行相關 pytest、`git diff --check`；不 commit／push。
