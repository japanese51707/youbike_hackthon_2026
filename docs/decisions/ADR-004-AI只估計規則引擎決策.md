# ADR-004：AI 只估計、規則引擎決策

狀態：已定案（2026-08-31）｜這是全專案最核心、不可違反的約束

## 決策

- **ML 模型只輸出估計值**（預測 + 不確定區間），不做任何決策
- **所有調度決策由確定性規則引擎/演算法做**（if-else、加權排序）
- 規則引擎吃預測的**區間下界**觸發，不吃點估計
- 所有調度指令走「預覽 → 人工確認 → 執行 → 驗證」閘門

## 脈絡

政府標案、有真人騎車受影響的場景，不能把決策交給黑盒子 AI（過不了採購與問責關）。這條約束沿用自「接住」專案的「不讓 LLM 決定資格」。

## 替代方案

- **端到端 ML 決策** — 模型直接輸出「要不要調度」。否決：不可解釋、不可究責、過不了政府採購。
- **分層（採用）** — ML 估計 + 規則決策。

## 理由

- **可解釋**：每個調度決策都能說出「為什麼觸發、依據什麼數字」
- **預測可失手，判斷不跟著失手**：吃區間下界，預測錯一次不會讓決策跟著錯
- **可究責**：決策邏輯是確定性規則，可稽核
- 對應知識庫〈對抗樣本與檢索脆弱性〉：學習模型有盲區，判斷該用確定性規則兜底

## 影響

- `calc_urgency()` 只算分數，不含③覆寫；覆寫在 dispatcher 排序當最前綴
- rule_engine 吃 lower_bound（config trigger 已定）
- 這條寫進 AGENTS.md + steering + CONTRIBUTING 當不可違反約束
- Demo 賣點：「AI 只猜數字，所有決策是可解釋規則」
