# ADR-301：AI 營運助理定位與 LLM 接入決策（advisory-only）

## 背景與問題

長官導覽面板新增「AI 營運助理」，目前為**前端 Demo 規則型**（ADR-205 範圍內：無外部服務、無金鑰、答案來自既有營運資料、缺值不捏造）。

是否進一步**接入真實 LLM**，牽涉多項尚未定案且跨後端/平台的因素：
- 專案定位明訂「這不是 ChatGPT 那種 AI」（requirements FR-1），核心是本機 LightGBM 預測 + 規則引擎。
- ADR-202/204 的地圖決策採無金鑰、零計費原則；直連第三方付費 API 與此精神衝突。
- ADR-004：AI 只估計，調度決策由確定性規則引擎 + 人工閘門。助理若給出可執行指令，可能讓**錯誤決策擴散**影響整個調度。
- LLM 有幻覺、成本、資安（金鑰、出向、prompt injection）風險。

此決策影響後端/平台，需 owner 與後端負責人共同決定，故本 ADR 先 `proposed`，**把「要不要接 LLM、怎麼接」留給後端決定**。

## 決策（proposed，待 owner／後端核准）

### 一、助理定位（不論是否接 LLM 都成立）

- 助理是**決策支援顧問（advisor）**，具備交通調度領域知識，目的在**最大化使用者對現況的理解、輔助做出更好的決策**。
- 助理只做：**摘要現況、解釋指標、示警風險、提出建議與其理由**。
- 助理**不得自行做出或執行調度決策**：調度是否觸發、派哪台車、去哪站，仍由**確定性規則引擎 + 人工閘門**決定（承接 ADR-004、人在迴圈）。
- 助理輸出**不得直接觸發派遣、寫入 dispatch payload 或改變系統狀態**；只在畫面上提供資訊與建議。
- 助理必須明確標示其性質（Demo 規則型／或 AI 生成），不得讓使用者誤認其建議為系統已執行的決策。

### 二、目前實作（已完成，屬 ADR-205）

- 前端規則型助理：進場自動摘要、可問答，答案由既有營運資料確定性產生；範圍外誠實回覆、不捏造；無外部服務、無金鑰、不進 payload。

### 三、LLM 接入選項（本 ADR 不定案，待後端決定）

- **選項 A：維持規則型／樣板助理（不接 LLM）**
  - 優點：零成本、零金鑰、可控、無幻覺、完全符合現有無金鑰原則。
  - 缺點：彈性低，只能回答預先設計的問題類型。
- **選項 B：接「後端代理」的 LLM（建議的接法，若要接）**
  - 金鑰只在後端、前端不持金鑰；以 RAG 灌入交通調度知識 + 即時營運數據；輸出限定 advisory。
  - 優點：語意彈性高、能解釋與情境化建議。
  - 缺點：成本、資安、幻覺風險，需完整護欄。
- **選項 C：前端直連第三方 LLM API**
  - 傾向否決：前端持金鑰、出向風險高，違反無金鑰原則。

### 四、若採選項 B 必須滿足的護欄（硬性）

- 金鑰只在後端、最小權限、可輪替；前端與版控不得出現金鑰。
- LLM 回應視為**不可信輸入**：不得直接執行、不得寫入 payload；數字以規則引擎／實際數據為準，助理不得虛構數值。
- **防幻覺**：涉及具體數據的回答必須引用系統實際值；無資料時回「不可用」，不得編造。
- 明確標示「AI 生成、僅供參考」；保留人工確認閘門。
- prompt injection 防護、輸出過濾、成本上限、用量與內容審計。

## 理由與判準

- 助理定位為 advisory 可提升決策品質，又不牴觸 ADR-004（決策仍由規則引擎＋人工）。
- 把 LLM 接入設為**待決策**，避免在未評估成本/資安前就鎖定生成式 AI，保留彈性。
- 後端代理（選項 B）是唯一符合無金鑰原則的接法；前端直連（選項 C）風險過高。

## 考慮過的替代方案

- **完全不做助理**：資訊密度不足、無決策輔助；已由 ADR-205 的 Demo 助理否決。
- **前端直連 LLM**：見選項 C，傾向否決。

## 影響與後果

### 正面
- 助理定位與護欄先講清楚，避免未來接 LLM 時越界成「AI 做決策」。
- LLM 接入保留為可評估的選項，不強迫也不排除。

### 負面與代價
- 規則型助理彈性有限；若不接 LLM，問答涵蓋度受限於預設規則。
- 若接 LLM，需投入後端代理、護欄與成本控管。

### 尚未解決
- 是否接 LLM、用哪家、成本上限、RAG 知識庫來源與更新，待後端/owner 決定。

## 介面與相容性

- 目前助理只讀既有前端營運資料，不改後端、API、Schema、dispatch payload。
- 若採選項 B，需新增「後端 LLM 代理」端點與 API 契約（屆時另立 3xx ADR 定案）。

## 資安與隱私

- 現況：無外部請求、無金鑰、無 PII。
- 若接 LLM：金鑰只在後端、輸出當不可信、防 prompt injection、不外流敏感營運/個資、審計與成本上限。

## 回復或取代方式

- 現況助理可直接移除，不影響其他功能。
- LLM 接入若採行後要退回，停用後端代理端點即可；方向改變以新 ADR supersede，不改寫本檔歷史。

## 驗證方式

- 現況：助理答案可追溯至既有營運資料；範圍外回「不可用」；操作檢查證明不進 payload、無外部請求。
- 若採選項 B：金鑰不在前端/版控；LLM 回應不觸發派遣；具體數字與系統值一致；有 AI 生成標示與人工閘門。
