YouBike 調度系統
白話版

我們要做的東西，用五張圖講完。看完你會知道：這系統在解決什麼問題、它怎麼運作、還有你負責哪一塊、跟別人怎麼接。

給誰看：隊友 B（空間工程師）、隊友 C（品質工程師），以及任何要在三分鐘內搞懂我們在做什麼的人。
不用先讀 spec。讀完這頁再去看 .kiro/specs/ 會順很多。
01 — 問題

車子每天都會自己跑到同一邊

YouBike 最常被罵的兩件事：要借的時候沒車、要還的時候沒位。這不是車不夠，是車在錯的地方。

02 — 系統在做什麼

提早發現 → 請人確認 → 派人去搬

整個系統從頭到尾就這一條線。中間有一個地方特別重要：系統永遠只給建議，真正要出車一定要有人按確認。

記住這句就好：AI 猜、規則判、人決定、調度員做。
03 — 關鍵觀念一

我們看「最壞的情況」，不看「最可能的情況」

預測不會只吐一個數字，它會吐一個範圍：最好會剩幾台、最可能剩幾台、最壞剩幾台。我們永遠拿最壞的那個去判斷要不要出車。

還有一個細節：安全線不是固定數字。每一站、每個時段的流失速度都不一樣——早上八點的學區站可能十分鐘就空，半夜的河濱站放兩台都夠。所以我們是拿「預測的最壞值」比對「安全緩衝」，不是寫死「少於 3 台就出車」。

04 — 關鍵觀念二

一個模型，一千五百多組參數

每站狀況都不同，但我們不做 1,583 個模型——那沒人維護得動，也沒辦法一起升級。做法是：一個共用的模型，每站掛一組自己的「條件參數」。

05 — 分工

三個人怎麼不互相踩到

規則只有一條：你交出去的東西，格式不能變。格式不變的前提下，裡面怎麼寫都是你家的事——想換演算法、想重寫元件，都不用問別人。

附錄

你會在文件裡看到的詞

spec 裡有些詞聽起來很硬，其實意思很簡單。

執行平面
負責「算」的那一堆程式。算完就忘，不記任何狀態，所以可以同時跑很多份。
控制平面
負責「決定和記帳」的那一堆。任務派給誰、做到哪一步、誰按了確認，都在這裡。
區間下界
預測範圍的最低那一端，也就是「最壞情況」。我們判斷要不要出車只看它。
安全緩衝
一站至少要留幾台才不算危險。預測的最壞值低於它就出車。
人在迴圈
系統不會自己動手，中間一定卡一個「等人按確認」的步驟。
閘門
就是那個要人按的按鈕。預覽 → 確認 → 執行 → 驗證，四步不能跳。
降級
即時資料抓不到時，改用歷史上同一時段的數字先頂著，而且畫面上要明講「這是舊資料」。
三層參數
基礎值、AI 每天微調、現場緊急覆寫。上層蓋下層，緊急那層過期就自己消失。
熱／溫／冷資料
最近兩週的放記憶體（要快）、三個月內的放 S3（拿來重訓練）、更久的歸檔或刪掉。
可抽換資料源
現場要接哪個即時資料還沒定。所以我們把入口統一，到時候換一個檔案就好，其他全都不用改。
接下來

你各自從哪裡開始

A（PM）
  • 先把資料格式定下來，產一份假資料
  • API 骨架先回假資料 —— 這一步不做完，B 和 C 都動不了
  • 然後才是決策邏輯和整合
B（空間）
  • 先讓 predict() 能跑、格式對，準不準之後再說
  • 記得回傳範圍，不是一個數字
  • 目前全站預測還沒接上，系統跑的是降級路徑 —— 這是你的第一個里程碑
C（品質）
  • 拿 A 的假資料先把三個畫面刻出來
  • 畫面上要看得出「這是舊資料」和「這是預測不是現況」
  • 確認按鈕不能只是前端藏起來，權限要後端擋
